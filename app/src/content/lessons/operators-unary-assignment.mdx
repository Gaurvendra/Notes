## Why this matters

`count = count++;` looks like it increments `count`. It doesn't: `count` stays exactly the same, forever, and a loop
waiting for it never ends. `stock += delivery;` compiles for a `short` even when the sum doesn't fit, and silently
turns 35,000 units into −30,536. And `hits++` on a field shared by two threads loses updates under load. The
increment and assignment operators are the most-used operators in Java, and each hides a precise rule about **when**
a value is read, **when** it's written and **which type** it's forced into.

## TL;DR

<Callout type="tldr">
- `i++` and `++i` both increment `i` **immediately**. The expression's value differs: `i++` is the **old** value,
  `++i` the **new** one. As a statement on its own (`i++;`) they're identical.
- `i = i++;` leaves `i` unchanged: the increment happens, then the assignment writes back the saved old value.
- Unary `-` and `+` **promote** `byte`, `short` and `char` to `int`; `!` works only on `boolean`.
- An assignment is an expression whose value is the assigned value, and `=` groups right to left: `a = b = 0`.
- `x op= y` means `x = (T) (x op y)`: a **hidden narrowing cast** (`byte b = 10; b += 300;` gives 54), with `x`
  evaluated **once** and its value saved **before** `y` is evaluated.
- `++`, `--` and `+=` on a shared field are **not atomic**: use `AtomicInteger` or a lock across threads.
</Callout>

## Mental model

Think of a variable as a **whiteboard** with a number on it. `++i` means "add one to the board, then read the board
aloud". `i++` means "note down what's on the board, add one to the board, then read your note aloud". Both change the
board right away; they only differ in what you say.

A compound assignment `x += y` is "note down x, work out y, add, and write the result back **in x's own size of
handwriting**": if the result doesn't fit, the extra digits are cut off without a word.

Where it breaks: when one expression reads and writes the same variable several times (`a + a++ + ++a`), you must
follow the notes exactly in left-to-right order. Code like that is legal, fully specified, and should never be
written.

## Concept, step by step

### 1. The unary operators

Unary operators take a single operand. Your notes list five, with this demo (outputs verified on a JVM):

```java title="Unary.java"
public class Unary {
    public static void main(String[] args) {
        int a = 5;
        System.out.println(a++);    // 5: prints the old value, a becomes 6
        System.out.println(++a);    // 7: a becomes 7, prints the new value
        System.out.println(a--);    // 7: prints 7, a becomes 6
        System.out.println(--a);    // 5: a becomes 5, prints 5
        boolean flag = true;
        System.out.println(!flag);  // false
        System.out.println(-a);     // -5
        System.out.println(+a);     // 5
    }
}
```

```text output
5
7
7
5
false
-5
5
```

| Operator | Name | Works on | Notes |
|---|---|---|---|
| `++x`, `x++` | Prefix / postfix increment | A numeric **variable** | Includes a narrowing cast back to the variable's type |
| `--x`, `x--` | Prefix / postfix decrement | A numeric variable | Same |
| `+x` | Unary plus | Numbers | Promotes `byte`, `short`, `char` to `int`; otherwise does nothing |
| `-x` | Unary minus | Numbers | Promotes; `-Integer.MIN_VALUE` overflows back to itself |
| `!x` | Logical NOT | `boolean` only | `!5` doesn't compile |
| `~x` | Bitwise NOT | Integers | `~x == -x - 1` ([Bitwise & Shift Operators](/lessons/bitwise-and-shift-operators/)) |
| `(type) x` | Cast | Any convertible value | [Type Conversion & Casting](/lessons/type-conversion/) |

### 2. Prefix versus postfix

Your notes say it precisely: postfix returns the value first, then increments; prefix increments first, then returns
the value. The JLS (§15.14.2) spells out the exact order for postfix: the old value is **saved**, the variable is
incremented and stored **at once**, and the saved old value becomes the value of the expression.

<PrefixPostfix />

That order explains the most famous trap:

```java title="The i = i++ trap"
int i = 5;
i = i++;                 // save 5, i becomes 6, then the assignment stores the saved 5
System.out.println(i);   // 5 (verified)
```

And the notes' two forms combined:

```java title="Mixing them"
int i = 5;
int j = i++ + ++i;       // left to right: i++ is 5 (i = 6), ++i is 7 (i = 7)
System.out.println(j + " " + i);   // 12 7
```

`++` and `--` need a **variable** (JLS §15.14.2): `5++`, `(a + b)++` and `++finalVariable` don't compile. They work on
every numeric type, with an implicit cast: `char c = 'a'; c++;` gives `'b'`, `double d = 1.5; d++;` gives 2.5, and
`byte b = 127; b++;` wraps to −128. On a wrapper (`Integer n`), `n++` unboxes, adds and boxes a **new** object.

### 3. Unary minus, unary plus and `!`

- `-x` negates. For integers it's `0 - x` with wrap-around, so `-Integer.MIN_VALUE == Integer.MIN_VALUE`
  ([Integer Types](/lessons/integer-types/)). For floating point it flips the sign bit: `-0.0` exists.
- `+x` is rarely written, but it's not a no-op on small types: `byte b = 1; byte c = +b;` doesn't compile, because
  `+b` is an `int`. The same goes for `-b`.
- `!x` negates a `boolean`: `!true` is `false`. Write `if (!isEmpty)` rather than `if (isEmpty == false)`.

### 4. Assignment is an expression

`=` stores the right-hand value in the left-hand variable, and the whole assignment has a **value**: the value
stored. `=` also groups **right to left**:

```java title="Assignment as an expression"
int a, b, c;
a = b = c = 7;                          // c = 7, then b = 7, then a = 7
String line;
while ((line = reader.readLine()) != null) {   // assign, then test the assigned value
    process(line);
}
```

The second pattern is idiomatic for readers; elsewhere, one assignment per statement is clearer. A typo worth knowing:
`x =+ 1;` compiles. It's `x = +1`, an assignment of plus one, not an increment.

### 5. Compound assignment: `+=` and friends

Java has 11 compound assignment operators: `+= -= *= /= %=`, the bitwise `&= |= ^=` and the shifts
`<<= >>= >>>=`. JLS §15.26.2 defines them exactly:

> `E1 op= E2` is equivalent to `E1 = (T) ((E1) op (E2))`, where `T` is the type of `E1`, except that `E1` is
> evaluated only once.

Three consequences, each a classic:

**1. A hidden narrowing cast.**

```java title="The hidden cast"
byte b = 10;
b += 300;              // compiles: b = (byte) (10 + 300) = (byte) 310 = 54 (verified)
b = b + 300;           // error: possible lossy conversion from int to byte
int total = 0;
total += 2.75;         // compiles: (int) 2.75 = 2
```

The cast is convenient for `byte` checksums and `char` arithmetic (`c += 1`), and dangerous everywhere else, because
it silences the compiler's "lossy conversion" error.

**2. The left side is evaluated once, and its value is saved first.**

```java title="Single evaluation"
int[] counts = new int[3];
int i = 0;
counts[i++] += 10;     // i++ runs once: counts[0] = 10, i = 1
int a = 5;
a += a++;              // save a (5), a++ is 5 (a = 6), 5 + 5 = 10 → a = 10
```

**3. The right side is one unit.** `s += 1 + 2` means `s = s + (1 + 2)`, not `s = s + 1 + 2`:

```java title="String +="
String s = "x";
s += 1 + 2;            // "x3": 1 + 2 is computed first
String t = "x";
t = t + 1 + 2;         // "x12": left to right, all concatenation
```

`+=` on a `String` is the only compound operator for objects. In loops it creates a new string each time: use a
`StringBuilder` ([Strings](/lessons/strings/)).

<TabItem label="Real world: appending to a buffer">

```java title="Buffer.java"
import java.util.Arrays;

public class Buffer {
    public static void main(String[] args) {
        int[] data = new int[4];
        int size = 0;

```

```text output

[0, 10, 20, 0] n=2
```

`array[size++] = value` is the standard "append" idiom: use the current size as the index, then grow it. The prefix
form skips slot 0 and overflows one step earlier. This is one of the few places where postfix-in-an-expression is
idiomatic; keep it to exactly this pattern.

</TabItem>
<TabItem label="Edge case: a counter that never counts">

```java title="NeverCounts.java"
public class NeverCounts {
    public static void main(String[] args) {
        int count = 0;
        for (int k = 0; k < 3; k++) {
            count = count++;     // a well-meant but wrong "increment"
        }
        System.out.println(count);
    }
}
```

```text output
0
```

Every iteration increments `count` and immediately overwrites it with the saved old value. In a `while (count < 10)`
loop the same line is an infinite loop. Write `count++;` or `count += 1;` as a statement of its own. Many IDEs and
static-analysis tools flag `x = x++`.

</TabItem>
<TabItem label="Real world: compound assignment hides overflow">

```java title="Stock.java"
public class Stock {
    public static void main(String[] args) {
        short stock = 30_000;
        stock += 5_000;          // compiles: (short) 35_000
        System.out.println(stock);
        // stock = stock + 5_000;   would not compile: possible lossy conversion from int to short
    }
}
```

```text output
-30536
```

The plain assignment would have been rejected, but `+=` casts silently: 35,000 − 65,536 = −30,536. Use `int` (or
`long`) for quantities, and `Math.addExact` where overflow must be an error. Reserve `byte`/`short` compound
arithmetic for code where wrapping is intended, such as checksums.

</TabItem>
<TabItem label="Anti-pattern → fix: several side effects in one expression">

```java title="Anti-pattern"
int a = 4;
a = a + a++ + ++a * --a + a--;   // your notes' example: legal, fully defined, unreadable
```

The result is 43 (verified): the operands are evaluated left to right as 4, 4, 6, 5, 5, giving 4 + 4 + 6 × 5 + 5, and
the final `a--` is overwritten by the assignment. Nobody should have to work that out in a code review.

```java title="Fix"
int a = 4;
int first = a;       // one side effect per statement, each with a name
a++;
// … write each step explicitly, in the order you mean
```

Rule of thumb: an expression may modify **one** variable, once, and only if that's the point of the expression
(`data[size++] = x`).

</TabItem>

## Under the hood

<details>
<summary>How ++ and += compile, and why they're not atomic</summary>

- **`iinc` for locals.** `i++;`, `++i;` and `i += 5;` on an `int` local compile to one instruction, `iinc`, which
  adds a constant to a local variable slot. As statements, `i++` and `++i` produce **identical** bytecode, so neither
  is faster.
- **Postfix in an expression** loads the old value onto the operand stack first, then increments the variable:
  `x = i++` is `iload i; iinc i 1; istore x`. That's the saved old value from the JLS, visible in bytecode.
- **The cast is real.** `b += 300` on a `byte` compiles to `iload`, `sipush 300`, `iadd`, `i2b`, `istore`: the
  `i2b` is the hidden narrowing.
- **Fields and array elements** have no `iinc`: `count++` on a field is `getfield`, `iconst_1`, `iadd`, `putfield`,
  a **read-modify-write** in three steps. Two threads can both read 5 and both write 6, losing an update. That's why
  shared counters use `AtomicInteger.incrementAndGet()` or `LongAdder`, which perform the update atomically.

</details>

## Myths vs facts

<MythVsFact myth="i++ increments i after the statement has finished.">
The increment happens **immediately**, during the evaluation of `i++`. Only the **value** of the expression is the
old one. That's why `i = i++` leaves `i` unchanged (the assignment runs last and stores the saved old value) and why
`i++ + i++` with `i = 1` is `1 + 2`.
</MythVsFact>

<MythVsFact myth="b += 1 is exactly the same as b = b + 1.">
Two differences (JLS §15.26.2): compound assignment includes a **cast** to the left side's type (`b = b + 1` doesn't
compile for a `byte`; `b += 1` does), and the left side is evaluated **only once** (`arr[i++] += 1` increments `i`
once, `arr[i++] = arr[i++] + 1` twice).
</MythVsFact>

<MythVsFact myth="++i is faster than i++.">
In Java, used as statements they compile to the same `iinc` instruction. (The advice comes from C++, where postfix on
an iterator object may copy it.) Choose by meaning; for a plain loop counter it makes no difference.
</MythVsFact>

<MythVsFact myth="count++ is a single, atomic operation.">
On a field it's three steps: read, add, write. Concurrent increments from several threads can overwrite each other.
Use `AtomicInteger`, `LongAdder` or synchronisation for shared counters.
</MythVsFact>

<MythVsFact myth="^ raises a number to a power.">
`^` is **exclusive or**: `2 ^ 3` is 1. Java has no power operator; use `Math.pow(2, 3)` (a `double`, 8.0), or a
shift for powers of two: `1 << 3` is 8.
</MythVsFact>

## Doubts cleared

<FaqItem q="What does `i = i++;` do?">
Nothing visible: the old value of `i` is saved, `i` is incremented, and then the assignment stores the saved value
back. It's always a bug; write `i++;`.
</FaqItem>

<FaqItem q="Can I use `++` on a `double`, a `char` or an `Integer`?">
Yes to all three. `double` adds 1.0; `char` moves to the next code unit (`'a'` → `'b'`) with an implicit cast; an
`Integer` is unboxed, incremented and boxed into a **new** `Integer` object (the old one is immutable).
</FaqItem>

<FaqItem q="Why does `byte b = 1; b = -b;` not compile?">
Unary minus promotes `byte` to `int`, so `-b` is an `int`, and assigning it to a `byte` is narrowing. Write
`b = (byte) -b;`, or use compound assignment (`b *= -1;` casts implicitly).
</FaqItem>

<FaqItem q="What is the value of an assignment expression?">
The value stored in the variable, after any conversion. That's why `a = b = 0` works (right to left) and why
`if (x = 5)` fails for an `int` (the value is an `int`, not a `boolean`), while `if (done = true)` compiles and is
always true.
</FaqItem>

<FaqItem q="In `a += f()`, is `a` read before or after `f()` runs?">
Before: the value of `a` is saved first, then `f()` runs, then the sum is stored (JLS §15.26.2). If `f()` changes `a`,
that change is lost.
</FaqItem>

<FaqItem q={'Why is `s += 1 + 2` different from `s = s + 1 + 2` for a String `s`?'}>
The right side of a compound assignment is evaluated as one expression: `s = s + (1 + 2)` gives `"x3"`. The plain
version groups left to right, `(s + 1) + 2`, which concatenates twice: `"x12"`.
</FaqItem>

<FaqItem q="Are there operators like `&&=` or `||=`?">
No. The compound operators are `+= -= *= /= %= &= |= ^= <<= >>= >>>=`. On booleans, `flag &= check()` compiles (the
non-short-circuit `&`), so `check()` always runs.
</FaqItem>

<FaqItem q="Should I ever use `++` inside a larger expression?">
Only in well-known idioms: `array[size++] = value`, `while (i-- > 0)`, `str.charAt(pos++)`. Everywhere else, put the
increment on its own line: the reader shouldn't have to track evaluation order.
</FaqItem>

## Pitfalls and best practices

| ✅ Do | ❌ Don't |
|---|---|
| Write increments as statements: `i++;`, `count += 2;` | Write `i = i++` or `x = x++ + ++x` |
| Use `array[size++] = v` for appends | Mix prefix and postfix in one expression |
| Use `int`/`long` for counters and quantities | Rely on `+=` with `byte`/`short` where overflow matters |
| Use `AtomicInteger`/`LongAdder` for counters shared by threads | Assume `count++` on a field is thread-safe |
| Put `!` in front of well-named booleans: `if (!isValid)` | Compare booleans with `== false` |
| Use `Math.pow` or shifts for powers | Write `^` for "to the power of" |

## Senior lens

<Callout type="senior" title="Explain it to your team in 60 seconds">
"`++` changes the variable immediately; postfix only hands you the old value, which is why `i = i++` is a no-op.
Compound assignment is a cast in disguise: `+=` compiles where `=` wouldn't, and silently wraps small types. And
neither `++` nor `+=` is atomic, so shared counters need atomics. Our rule: one side effect per statement, except
the `array[size++]` idiom."
</Callout>

**Where these operators cause production bugs**

| Place | Symptom | Prevention |
|---|---|---|
| Loop counters assigned from themselves | Loops that never end or never count | Lint rule for `x = x++`; code review |
| Small-type accumulators with `+=` | Quantities that turn negative | `int`/`long`, `Math.addExact` |
| Metrics counters on shared objects | Under-counted requests under load | `LongAdder`, `AtomicLong`, or a metrics library |
| Expressions with several side effects | Behaviour nobody can predict in review | One side effect per statement |
| `String +=` in loops | Quadratic time on large inputs | `StringBuilder`, `String.join`, `Collectors.joining` |

**Code-review checklist**
- [ ] No variable is modified more than once in an expression, and none is read after being modified in it.
- [ ] Compound assignments on `byte`/`short`/`char` are intentional (wrapping expected).
- [ ] Counters touched by several threads are atomic.

## Modern Java

- <VersionBadge since={5} /> `AtomicInteger.incrementAndGet()` and friends (`java.util.concurrent.atomic`) for
  thread-safe `++`.
- <VersionBadge since={8} /> `LongAdder`, which scales better than `AtomicLong` for counters updated by many threads;
  `Math.incrementExact` and `Math.negateExact`, which throw on overflow.
- The operators themselves are unchanged since Java 1.0. Static analysers (IntelliJ inspections, Error Prone,
  SpotBugs) flag self-assignment, `x = x++` and narrowing compound assignment.

```java title="Ops.java (solution)"
package track.operators_unary_assignment;

/** Reference solution for the Ops exercise. */
public final class Ops {

    private Ops() {
    }

    public static int postIncrement(int[] box) {
        int old = box[0];           // save the old value
        box[0] = old + 1;           // increment at once (int addition wraps at MAX_VALUE)
        return old;                 // the expression's value is the saved one
    }

    public static int preDecrement(int[] box) {
        box[0] = box[0] - 1;
        return box[0];              // the expression's value is the new one
    }
```

```java title="Luhn.java (solution)"
package track.operators_unary_assignment;

/** Reference solution for the Luhn exercise. */
public final class Luhn {

    private Luhn() {
    }

    public static boolean isValid(String number) {
        int sum = 0;
        int digits = 0;
        boolean doubleIt = false;                   // the rightmost digit is not doubled
        for (int i = number.length() - 1; i >= 0; i--) {
            char c = number.charAt(i);
            if (c == ' ') {
                continue;
            }
            if (c < '0' || c > '9') {
                return false;
            }
            sum += weighted(c - '0', doubleIt);
            doubleIt = !doubleIt;
            digits++;
        }
        return digits >= 2 && sum % 10 == 0;
    }

    public static int checkDigit(String payload) {
        if (payload.isEmpty()) {
            throw new IllegalArgumentException("empty payload");
        }
        int sum = 0;
        boolean doubleIt = true;                    // the check digit will be appended to the right
        for (int i = payload.length() - 1; i >= 0; i--) {
            char c = payload.charAt(i);
            if (c < '0' || c > '9') {
                throw new IllegalArgumentException("not a digit: " + c);
            }
            sum += weighted(c - '0', doubleIt);
            doubleIt = !doubleIt;
        }
        return (10 - sum % 10) % 10;
    }

    private static int weighted(int digit, boolean doubleIt) {
        if (!doubleIt) {
            return digit;
        }
        int d = digit * 2;
        if (d > 9) {
            d -= 9;                                 // same as adding the two digits of d
        }
        return d;
    }
}
```

```java title="SideEffects.java (solution)"
package track.operators_unary_assignment;

import java.util.ArrayList;
import java.util.List;

/** Reference solution for the SideEffects exercise: tokenise, then evaluate while parsing, left to right. */
public final class SideEffects {

    private static final List<String> SYMBOLS = List.of("++", "--", "+=", "-=", "*=", "=", "+", "-", "*", "(", ")");

    private final List<String> tokens;
    private int pos;
    private int a;
    private int b;

    private SideEffects(List<String> tokens, int a, int b) {
        this.tokens = tokens;
        this.a = a;
        this.b = b;
    }

    public static int[] execute(String statement, int a, int b) {
        SideEffects s = new SideEffects(tokenize(statement), a, b);
        s.statement();
        if (s.pos != s.tokens.size()) {
            throw new IllegalArgumentException("unexpected " + s.tokens.get(s.pos));
        }
        return new int[] {s.a, s.b};
    }

    private void statement() {
        String target = variable();
        String op = next();
        switch (op) {
            case "=" -> set(target, expression());
            case "+=", "-=", "*=" -> {
                int saved = get(target);                 // the left value is saved before the right side runs
                int value = expression();
                set(target, switch (op) {
                    case "+=" -> saved + value;
                    case "-=" -> saved - value;
                    default -> saved * value;
                });
            }
            default -> throw new IllegalArgumentException("assignment operator expected, got " + op);
        }
    }

    private int expression() {
        int value = term();
        while (peek("+") || peek("-")) {
            value = next().equals("+") ? value + term() : value - term();
        }
        return value;
    }

    private int term() {
        int value = unary();
        while (peek("*")) {
            next();
            value = value * unary();
        }
        return value;
    }

    private int unary() {
        if (peek("++") || peek("--")) {
            int delta = next().equals("++") ? 1 : -1;
            String v = variable();
            set(v, get(v) + delta);
            return get(v);                               // prefix: the new value
        }
        if (peek("-")) {
            next();
            return -unary();
        }
        if (peek("(")) {
            next();
            int value = expression();
            expect(")");
            return value;
        }
        String token = next();
        if (token.equals("a") || token.equals("b")) {
            int old = get(token);
            if (peek("++") || peek("--")) {
                set(token, old + (next().equals("++") ? 1 : -1));   // postfix: increment now…
            }
            return old;                                  // …but yield the old value
        }
        try {
            return Integer.parseInt(token);
        } catch (NumberFormatException e) {
            throw new IllegalArgumentException("unexpected " + token, e);
        }
    }

    private String variable() {
        String t = next();
        if (!t.equals("a") && !t.equals("b")) {
            throw new IllegalArgumentException("variable expected, got " + t);
        }
        return t;
    }

    private int get(String v) {
        return v.equals("a") ? a : b;
    }

    private void set(String v, int value) {
        if (v.equals("a")) {
            a = value;
        } else {
            b = value;
        }
    }

    private boolean peek(String t) {
        return pos < tokens.size() && tokens.get(pos).equals(t);
    }

    private String next() {
        if (pos >= tokens.size()) {
            throw new IllegalArgumentException("unexpected end of input");
        }
        return tokens.get(pos++);
    }

    private void expect(String t) {
        if (!next().equals(t)) {
            throw new IllegalArgumentException("expected " + t);
        }
    }

    private static List<String> tokenize(String s) {
        List<String> out = new ArrayList<>();
        int i = 0;
        while (i < s.length()) {
            char c = s.charAt(i);
            if (c == ' ') {
                i++;
            } else if (Character.isDigit(c)) {
                int start = i;
                while (i < s.length() && Character.isDigit(s.charAt(i))) {
                    i++;
                }
                out.add(s.substring(start, i));
            } else if (Character.isLetter(c)) {
                out.add(String.valueOf(c));
                i++;
            } else {
                final int at = i;
                String symbol = SYMBOLS.stream().filter(sym -> s.startsWith(sym, at)).findFirst()   // longest first
                        .orElseThrow(() -> new IllegalArgumentException("unexpected '" + c + "'"));
                out.add(symbol);
                i += symbol.length();
            }
        }
        return out;
    }
}
```

## Cheat sheet

<CheatSheet>

| Topic | Remember |
|---|---|
| **`i++` vs `++i`** | both increment at once; value: old (`i++`) vs new (`++i`); identical as statements |
| **`i = i++`** | no change: save old, increment, assignment stores old |
| **Notes' demo** | `a = 5`: `a++` 5, `++a` 7, `a--` 7, `--a` 5, `!true` false, `-a` −5, `+a` 5 |
| **Unary `+`/`-`** | promote `byte`/`short`/`char` to `int`; `-MIN_VALUE == MIN_VALUE` |
| **`!`** | booleans only |
| **Assignment** | an expression; value = stored value; right to left: `a = b = 0`; beware `x =+ 1` |
| **`x op= y`** | `x = (T) (x op y)`, `x` evaluated once, its value saved **before** `y` runs |
| **Hidden cast** | `byte b = 10; b += 300;` → 54; `short s = 30_000; s += 5_000;` → −30,536 |
| **String `+=`** | `s += 1 + 2` → `s + "3"` (right side is one unit) |
| **Threads** | `++`/`+=` on fields aren't atomic: `AtomicInteger`, `LongAdder` |
| **No power operator** | `^` is XOR; `Math.pow`, `1 << n` |

</CheatSheet>
