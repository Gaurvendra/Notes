## Why this matters

A tax rate changes from 18% to 20%. The rule "price times rate, rounded to the cent" was written out in five places:
the checkout, the invoice, the refund, the report and an export job. Four are updated; the export job keeps using 18%
for a month, and the finance team spends a week reconciling. The fix is not clever code; it's a **method**: one named
place for one rule, called from everywhere that needs it. Methods are how a program gets names for its ideas, how a
bug gets fixed once instead of five times, and how code becomes testable piece by piece.

## TL;DR

<Callout type="tldr">
- A **method** is a named block of code that does one task: it takes **parameters**, may **return** a value, and can
  be called from many places (readability and reuse).
- A declaration has **modifiers**, a **return type** (or `void`), a **name**, a **parameter list**, an optional
  **`throws`** clause and a **body**.
- The **signature** is the name plus the parameter types only: `sum(int, int)`. The return type is **not** part of
  it.
- **Parameters** are the variables in the declaration; **arguments** are the values you pass in a call. Arguments are
  evaluated left to right and **copied** into the parameters.
- A method ends at a `return`, at its closing brace (only `void` methods), or when an **exception** leaves it. A
  non-`void` method must return a value on every path.
- Good methods: a verb name in camelCase, one job, few parameters, no hidden side effects.
</Callout>

## Mental model

A method is a **kitchen appliance** with a label on the front. You put ingredients in (arguments), it works on its
own copies inside (parameters and local variables), and it hands back one result (the return value) or just does its
job (`void`). You don't need to know how the blender works to use it; its name and its inputs tell you what it does.

Where the analogy breaks: a method can also have **side effects** (print, change an object, write a file), and it can
stop with an exception instead of a result.

## Concept, step by step

### 1. What a method is, and why

A method is a collection of statements that performs one task, with a name. The notes' example: `sum` adds two
numbers and logs the result, and `getPriceOfPen` **reuses** it instead of repeating the addition and the logging:

```java title="Calculation.java"
public class Calculation {

    public int sum(int val1, int val2) {
        int total = val1 + val2;
        // doing some logging stuff
        System.out.println("addition of val1 and val2 is:" + total);
        return total;
    }

    public int getPriceOfPen() {
        int capPrice = 2;
        int penBodyPrice = 5;
        int totalPenPrice = sum(capPrice, penBodyPrice);
        return totalPenPrice;
    }

    public static void main(String[] args) {
        System.out.println(new Calculation().getPriceOfPen());
    }
}
```

```text output
addition of val1 and val2 is:7
7
```

Two benefits, as the notes say: **readability** (`getPriceOfPen` reads as a sentence, and the name `sum` explains
three lines) and **reusability** (the logging rule lives in one place). A third one matters just as much at work:
**testability**, since a small method with clear inputs and outputs is easy to test on its own.

### 2. Anatomy of a declaration

The notes' template, `public int sum(int a, int b) throws Exception { … }`, has every part:

| Part | In the example | Rules |
|---|---|---|
| **Modifiers** | `public` | Access (`public`, `protected`, `private`, or none = package-private) plus others such as `static`, `final`, `abstract`, `synchronized` ([Packages & Access Modifiers](/lessons/packages-access-modifiers/)) |
| **Return type** | `int` | Any type, or `void` for "returns nothing" |
| **Name** | `sum` | An identifier; by convention a verb in camelCase |
| **Parameter list** | `(int a, int b)` | Zero or more `Type name` pairs, comma-separated; `()` when empty |
| **`throws` clause** | `throws Exception` | Optional: checked exceptions the method may throw ([Exceptions Basics](/lessons/exceptions-basics/)) |
| **Body** | `{ … }` | The statements; `abstract` and interface methods may have `;` instead |

The **signature** of a method is its **name and parameter types**: `sum(int, int)`. Not the return type, not the
parameter names, not the modifiers, not the `throws` clause (JLS §8.4.2). Two methods in a class can't have the same
signature, so these two can't coexist even though their return types differ:

```java title="Duplicate.java"
public class Duplicate {
    int total(int a, int b) { return a + b; }
    long total(int a, int b) { return a + b; }   // compile error: total(int,int) is already defined
}
```

The same name with **different parameter types** is allowed: that's overloading, the topic of
[Overloading](/lessons/overloading-resolution/).

### 3. Parameters and arguments

**Parameters** are the variables declared in the method's header; **arguments** are the values written in a call.
When you call `sum(capPrice, penBodyPrice)`:

1. The argument expressions are evaluated **left to right** (JLS §15.12.4.2).
2. A new frame is pushed for `sum` ([The Call Stack](/lessons/call-stack/)), and each parameter is a **new local
   variable** initialised with a **copy** of its argument's value.
3. The body runs, using only its parameters, its locals, fields and other methods.

Because parameters are copies, assigning to a parameter never changes the caller's variable (for objects, the
*reference* is copied; see [Pass-by-Value](/lessons/pass-by-value/)):

```java title="Copies.java"
public class Copies {
    static void reset(int n) {
        n = 0;                      // changes the copy only
    }

    public static void main(String[] args) {
        int count = 5;
        reset(count);
        System.out.println(count);
    }
}
```

```text output
5
```

A parameter can be declared `final` so the method can't reassign it. Java has no default values for parameters: use
overloading or a small builder instead.

### 4. Return values and `void`

The return type says what the method gives back. `return expression;` ends the method and hands the value to the
caller; the value must be assignable to the return type. A `void` method returns nothing: it ends at its closing
brace, or earlier with a plain `return;` (the notes point this out: `return` stops even a `void` method).

A method with a return type must return on **every** path; if the body can reach its end, the compiler reports
"missing return statement" (JLS §8.4.7). And a method can also end **abruptly**, when an exception is thrown and not
caught inside it; then it returns no value at all, and the exception travels to the caller.

```java title="Returns.java"
public class Returns {
    static String sign(int x) {
        if (x > 0) {
            return "positive";      // leaves the method at once
        }
        if (x < 0) {
            return "negative";
        }
        return "zero";              // without this line: "missing return statement"
    }

    static void greet(String name) {
        if (name == null || name.isBlank()) {
            System.out.println("Hello, stranger");
            return;                 // early exit from a void method
        }
        System.out.println("Hello, " + name);
    }

    public static void main(String[] args) {
        System.out.println(sign(-3) + " " + sign(0));
        greet(null);
        greet("Ada");
    }
}
```

```text output
negative zero
Hello, stranger
Hello, Ada
```

A method returns **one** value. To return several, return an object that holds them, today usually a `record`
([POJO, JavaBean, DTO & Records](/lessons/pojo-javabean-dto-records/)). The caller may ignore a return value, which is
sometimes fine (`list.add(x)` returns a `boolean` nobody reads) and sometimes a bug (see the puzzles below).

### 5. Names

Method names are verbs or verb phrases in camelCase: `calculateTotal`, `sendEmail`, `toString`. Conventions that
make code read like prose:

| Kind | Pattern | Examples |
|---|---|---|
| Actions | verb + object | `saveOrder`, `parseLine`, `closeConnection` |
| Questions (`boolean`) | `is`, `has`, `can`, `should` | `isEmpty`, `hasNext`, `canRetry` |
| Accessors | `get`/`set` + property (beans), or just the property (records) | `getName`, `setName`, `name()` |
| Conversions | `to…`, `as…`, `from…`, `of…` | `toString`, `asList`, `Duration.ofSeconds` |

A good name describes **what** the method achieves, not **how**: `findCheapestFlight`, not `loopOverFlightsAndCompare`.
If you can't name a method without "and", it probably does two jobs.

### 6. Kinds of methods

The notes split methods into "system-defined" and "user-defined". The standard terms are **Java SE API methods**
(library methods such as `Math.sqrt`, `String.length`, `List.of`) and **your own methods**. More useful at work are
the kinds by how a method is declared and called:

| Kind | Declared with | Called as | Lesson |
|---|---|---|---|
| Instance method | no `static` | `object.method()` (has `this`) | [static vs Instance](/lessons/static-vs-instance/) |
| Static method | `static` | `ClassName.method()` | [static vs Instance](/lessons/static-vs-instance/) |
| Overloaded methods | same name, different parameter types | chosen at compile time | [Overloading](/lessons/overloading-resolution/) |
| Overriding method | same signature as a supertype method | chosen at run time | [Polymorphism](/lessons/polymorphism/) |
| Abstract method | `abstract`, no body | implemented by a subclass | [Abstract Classes](/lessons/abstract-classes/) |
| Final method | `final` | can't be overridden | [Inheritance](/lessons/inheritance/) |
| Varargs method | `Type... name` as the last parameter | any number of arguments | [Varargs](/lessons/varargs/) |

Methods are always declared inside a class, interface, enum or record. There are no free-standing functions in Java,
and no methods inside methods (a local class or a lambda can play that role).

### 7. Designing good methods

- **One job.** A method that validates, computes, logs and saves is four methods waiting to be extracted.
- **Few parameters.** Three is comfortable; beyond four, group related values into an object or record. Several
  parameters of the same type (`move(int, int, int, int)`) invite mixed-up arguments.
- **No flag parameters.** `print(order, true)` hides what `true` means; two methods (`printSummary`, `printDetails`)
  or an enum say it.
- **Commands or queries.** A method either *does* something (a command, often `void`) or *answers* something (a query,
  no side effects). Mixing them surprises callers: a `getTotal()` that also saves to the database.
- **Validate at the boundary.** Public methods check their arguments and fail fast with a clear exception
  (`Objects.requireNonNull`, `IllegalArgumentException`); private helpers can trust their callers.
- **Document the contract.** Javadoc with `@param`, `@return` and `@throws` for anything others will call.

</TabItem>
<TabItem label="Edge case: missing return statement">

```java title="Grade.java"
static String grade(int score) {
    if (score >= 50) {
        return "pass";
    } else if (score < 50) {
        return "fail";
    }
}   // compile error: missing return statement
```

Every `int` is either `>= 50` or `< 50`, yet this doesn't compile. The compiler doesn't reason about what conditions
mean: an `if` without a final `else` can complete normally (JLS §14.22), so the end of the method is reachable, and a
method with a return type must not reach its end (JLS §8.4.7). Fix it with a plain `else`, or a single expression:

```java title="Fixed"
static String grade(int score) {
    return score >= 50 ? "pass" : "fail";
}
```

</TabItem>
<TabItem label="Anti-pattern → fix: flag parameters">

```java title="Anti-pattern"
report(order, true, false);   // what do true and false mean here?

static void report(Order order, boolean detailed, boolean email) { … }
```

Each `boolean` parameter doubles the paths through the method, and call sites don't say what they want. Split by
intent, or pass a small enum:

```java title="Fix"
printSummary(order);
printDetails(order);
emailDetails(order);

// or, when the variants really share code:
report(order, Detail.FULL, Channel.EMAIL);
```

</TabItem>
<TabItem label="Real world: guard clauses at the boundary">

```java title="Transfers.java"
import java.util.Objects;

public class Transfers {
    static long transfer(long balanceCents, long amountCents, String reference) {
        Objects.requireNonNull(reference, "reference");
        if (amountCents <= 0) {
            throw new IllegalArgumentException("amount must be positive: " + amountCents);
        }
        if (amountCents > balanceCents) {
            throw new IllegalArgumentException("insufficient funds");
        }
        return balanceCents - amountCents;       // the happy path, unindented
    }

    public static void main(String[] args) {
        System.out.println(transfer(10_000, 2_500, "rent"));
        try {
            transfer(10_000, -1, "oops");
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

```text output
7500
amount must be positive: -1
```

The method refuses bad input before doing anything, with a message that names the problem. Callers find mistakes
immediately, at the call that made them, instead of three layers later ([Conditionals](/lessons/conditionals/) shows
guard clauses in general).

## Under the hood

<details>
<summary>Methods in the class file and in the JVM</summary>

- **Descriptors.** In a class file each method is stored with its name and a **descriptor** that encodes the
  parameter types *and* the return type (JVMS §4.3.3): `int sum(int, int)` is `sum:(II)I`, `void main(String[])` is
  `main:([Ljava/lang/String;)V`, `String name()` is `name:()Ljava/lang/String;`. The JVM could tell methods apart by
  return type; the Java language doesn't allow it, but the compiler uses it for generated **bridge methods**
  ([Type Erasure & Limitations](/lessons/generics-erasure-and-limitations/)).
- **Call instructions.** Static calls compile to `invokestatic`, calls on objects to `invokevirtual` (classes) or
  `invokeinterface` (interfaces), constructors and `super.m()` to `invokespecial`, and lambdas or string
  concatenation to `invokedynamic`.
- **Frames.** Each call gets a frame with a local-variable array and an operand stack, sized at compile time
  (`max_locals`, `max_stack`). The parameters occupy the first local slots, after `this` in slot 0 for an instance
  method; a `long` or `double` takes two slots (JVMS §2.6). See [The Call Stack](/lessons/call-stack/).
- **Inlining.** The JIT compiler copies the bodies of small and frequently called methods into their callers, so a call
  to a tiny helper usually costs nothing at run time ([How Java Runs](/lessons/how-java-runs/)). Splitting code into
  well-named methods is not a performance trade-off.

</details>

## Myths vs facts

<MythVsFact myth="The return type is part of a method's signature." audit="7.2">
The signature is the **name plus the parameter types** (JLS §8.4.2). The return type, the parameter names, the
modifiers and the `throws` clause are not part of it, so two methods that differ only in return type can't be declared
in the same class.
</MythVsFact>

<MythVsFact myth="A method finishes only at a return statement or at its closing brace." audit="7.6">
It also finishes **abruptly** when an exception is thrown and not caught inside it. Then no value is returned, and the
exception continues to the caller ([Exceptions Basics](/lessons/exceptions-basics/)).
</MythVsFact>

<MythVsFact myth="Java has system-defined methods and user-defined methods." audit="7.7">
That's a useful idea with non-standard names. The usual terms are **Java SE API** (or library) methods, such as
`Math.sqrt` and `String.length`, and your own methods. For design, the distinctions that matter are instance vs static,
overloading vs overriding, abstract and final.
</MythVsFact>

<MythVsFact myth="Many small methods make a program slow because every call has a cost.">
Hot, small methods are **inlined** by the JIT compiler: their code is copied into the caller, and the call disappears.
Readable decomposition is almost never the performance problem; measure before merging methods for speed.
</MythVsFact>

<MythVsFact myth="A void method can't contain return.">
`return;` (without a value) is allowed in a `void` method and ends it early, as the notes say. What's not allowed is
`return value;` in a `void` method, or a plain `return;` in a method that must return a value.
</MythVsFact>

## Doubts cleared

<FaqItem q="What's the difference between a parameter and an argument?">
The parameter is the variable in the declaration (`int a` in `sum(int a, int b)`); the argument is the value you pass
when calling (`2` in `sum(2, 5)`). At the call, each parameter is initialised with a copy of its argument.
</FaqItem>

<FaqItem q="Can a method return two values?">
Not directly. Return an object that holds both: a `record` is the modern way (`record MinMax(int min, int max)`), or
an array or a collection when the values are of one kind. Avoid "output parameters" (mutating an array you were
given) unless there's a strong reason.
</FaqItem>

<FaqItem q="Can I declare a method inside another method?">
No. You can declare a local class (or local record, enum or interface) inside a method, or use a lambda for a small
function, but not a method directly. Usually a `private` method in the same class is the right answer.
</FaqItem>

<FaqItem q="Does the order of methods in a class matter?">
Not for the compiler: a method can call another one declared further down. For readers, it does: a common convention is
public methods first, each followed by the private helpers it uses, so the file reads top-down.
</FaqItem>

<FaqItem q={'Why does main say "non-static method cannot be referenced from a static context"?'}>
`main` is `static`, so there's no object (`this`) to call an instance method on. Either create an object
(`new Calculation().getPriceOfPen()`, as in the example) or make the helper `static` if it doesn't use instance state.
[static vs Instance](/lessons/static-vs-instance/) explains the rule.
</FaqItem>

<FaqItem q="How many parameters is too many?">
There's no hard limit (the JVM allows up to 255 slots), but readability drops fast after three or four. Group values
that travel together into a record, or use a builder for many optional settings.
</FaqItem>

<FaqItem q="What's the difference between a method and a function?">
In Java every method belongs to a class or interface. A `static` method that depends only on its parameters is what
other languages call a function; a lambda is an object implementing a functional interface. "Function" in Java usually
means one of those.
</FaqItem>

<FaqItem q="Should every method validate its arguments?">
Public and protected methods, which strangers call, should (fail fast, with a clear message). Private helpers are
called only from your own class, so they can rely on the checks already done; `assert` can document their assumptions.
</FaqItem>

<FaqItem q="Does Java have default parameter values?">
No. Overload the method (`connect(host)` calls `connect(host, 443)`), or use a builder or a record with sensible
defaults for many options.
</FaqItem>

## Pitfalls and best practices

| ✅ Do | ❌ Don't |
|---|---|
| Name methods with verbs that say what they achieve | Name them after how they work (`loopAndCheck`) |
| Keep one job per method; extract when a comment explains a block | Write 200-line methods with sections |
| Return a value (or a record) from queries | Mutate an argument to "return" something |
| Use enums or separate methods instead of `boolean` flags | Call `report(order, true, false)` |
| Validate public inputs and fail fast | Let bad input travel deep before it breaks |
| Use the return values of `String`, `BigDecimal` and other immutable types | Call `s.trim();` and ignore the result |

## Senior lens

<Callout type="senior" title="Explain it to your team in 60 seconds">
"A method is our unit of naming, reuse and testing. Each one does one job its name describes, takes few parameters and
either answers a question or performs an action, not both. Public methods check their inputs and document their
contract; private helpers keep the public ones short. Don't worry about the cost of small methods: the JIT inlines
them. Worry about duplicated rules: every rule should have exactly one home."
</Callout>

**Method design trade-offs**

| Choice | Benefit | Cost | Use when |
|---|---|---|---|
| Many small methods | Names document intent, easy to test | More jumps when reading | Almost always, with good names |
| Few long methods | Everything in one place | Hard to test, review and change | Rarely: short scripts, generated code |
| Record as a return type | Several values, named, immutable | One more type | A query has more than one result |
| Parameter object | Short signatures, validated once | A new type | Values travel together (a date range, a money amount) |
| Overloads for defaults | Simple call sites | Overload ambiguity risks | One or two optional values |

**Code-review checklist**
- [ ] Each method's name says what it does; nothing needs "and".
- [ ] No method is longer than a screen without a very good reason.
- [ ] No `boolean` flag parameters; at most three or four parameters.
- [ ] Queries have no side effects; commands are clearly named.
- [ ] Public methods validate arguments; return values of immutable types are used.

## Modern Java

- <VersionBadge since={5} /> Varargs (`int... values`) and the `@Override` annotation ([Varargs](/lessons/varargs/)).
- <VersionBadge since={8} /> Lambdas and method references (`Math::abs`), and `default` and `static` methods in
  interfaces.
- <VersionBadge since={9} /> `private` methods in interfaces.
- <VersionBadge since={10} /> `var` for local variables only: not for parameters, fields or return types (lambda
  parameters can use `var` since Java 11).
- <VersionBadge since={16} /> Records generate accessor methods (`name()`), a common way to return several values.
- <VersionBadge since={25} jep={512} /> Instance main methods and compact source files: a program can start with
  `void main() { … }`, without `public static` or `String[] args` ([Your First Program](/lessons/first-program/)).

```java title="TextStats.java (solution)"
public final class TextStats {

    private TextStats() {
    }

    public static int wordCount(String text) {
        return words(text).length;
    }

    public static int vowelCount(String text) {
        Objects.requireNonNull(text, "text");
        int count = 0;
        for (int i = 0; i < text.length(); i++) {
            if (isVowel(text.charAt(i))) {
                count++;
            }
        }
        return count;
    }

    public static String longestWord(String text) {
        String longest = "";
        for (String w : words(text)) {
            if (w.length() > longest.length()) {      // strictly longer: the first of equals wins
                longest = w;
            }
        }
        return longest;
    }

    public static String initials(String fullName) {
        StringBuilder sb = new StringBuilder();
        for (String w : words(fullName)) {
            sb.append(Character.toUpperCase(w.charAt(0)));
        }
        return sb.toString();
    }

    /** The one place that knows what a word is; the public methods reuse it. */
    private static String[] words(String text) {
        Objects.requireNonNull(text, "text");
        String trimmed = text.strip();
        return trimmed.isEmpty() ? new String[0] : trimmed.split("[ \\t\\n]+");
    }

    private static boolean isVowel(char c) {
        return "aeiouAEIOU".indexOf(c) >= 0;
    }
```

```java title="Invoice.java (solution)"
package track.methods_basics;

/** Reference solution for the Invoice exercise. */
public final class Invoice {

    private static final long MAX_UNIT_CENTS = 10_000_000;
    private static final int MAX_QUANTITY = 10_000;
    private static final int MAX_LINES = 1_000;

    private Invoice() {
    }

    public static long lineTotal(long unitCents, int quantity) {
        check(unitCents >= 0 && unitCents <= MAX_UNIT_CENTS, "unit price out of range: " + unitCents);
        check(quantity >= 0 && quantity <= MAX_QUANTITY, "quantity out of range: " + quantity);
        return unitCents * quantity;                 // at most 10^11: no overflow
    }

    public static long discount(long amountCents, int percent) {
        check(amountCents >= 0, "negative amount: " + amountCents);
        check(percent >= 0 && percent <= 100, "percent out of range: " + percent);
        return divideHalfEven(amountCents * percent, 100);
    }

    public static long tax(long amountCents, int basisPoints) {
        check(amountCents >= 0, "negative amount: " + amountCents);
        check(basisPoints >= 0 && basisPoints <= 10_000, "basis points out of range: " + basisPoints);
        return divideHalfEven(amountCents * basisPoints, 10_000);
    }

    public static long total(long[] unitCents, int[] quantities, int discountPercent, int taxBasisPoints) {
        check(unitCents.length == quantities.length, "prices and quantities differ in length");
        check(unitCents.length <= MAX_LINES, "too many lines: " + unitCents.length);
        long sum = 0;
        for (int i = 0; i < unitCents.length; i++) {
            sum += lineTotal(unitCents[i], quantities[i]);
        }
        long net = sum - discount(sum, discountPercent);
        return net + tax(net, taxBasisPoints);
    }

    public static String format(long cents) {
        check(cents >= 0, "negative amount: " + cents);
        return (cents / 100) + "." + String.format("%02d", cents % 100);
    }

    /** numerator / denominator rounded half-even, for numerator ≥ 0 and denominator > 0. */
    private static long divideHalfEven(long numerator, long denominator) {
        long quotient = numerator / denominator;
        long twiceRemainder = 2 * (numerator % denominator);
        if (twiceRemainder > denominator || (twiceRemainder == denominator && quotient % 2 != 0)) {
            quotient++;
        }
        return quotient;
    }

    private static void check(boolean ok, String message) {
        if (!ok) {
            throw new IllegalArgumentException(message);
        }
    }
}
```

```java title="Scores.java (solution)"
package track.methods_basics;

import java.util.Arrays;
import java.util.Objects;

/** Reference solution for the Scores exercise. */
public final class Scores {

    public record Report(int count, int min, int max, double mean, double median, int mode, double stdDev) {
    }

    private Scores() {
    }

    public static Report report(int[] scores) {
        check(scores);
        int min = scores[0];
        int max = scores[0];
        for (int s : scores) {
            min = Math.min(min, s);
            max = Math.max(max, s);
        }
        return new Report(scores.length, min, max, mean(scores), median(scores), mode(scores), stdDev(scores));
    }

    public static double mean(int[] scores) {
        check(scores);
        long sum = 0;
        for (int s : scores) {
            sum += s;
        }
        return (double) sum / scores.length;
    }

    public static double median(int[] scores) {
        check(scores);
        int[] sorted = scores.clone();                 // sort a copy: the caller's array must not change
        Arrays.sort(sorted);
        int mid = sorted.length / 2;
        return sorted.length % 2 == 1 ? sorted[mid] : (sorted[mid - 1] + sorted[mid]) / 2.0;
    }

    public static int mode(int[] scores) {
        check(scores);
        int[] counts = new int[101];
        for (int s : scores) {
            counts[s]++;
        }
        int best = 0;
        for (int v = 1; v <= 100; v++) {
            if (counts[v] > counts[best]) {            // strictly greater: ties keep the smaller score
                best = v;
            }
        }
        return best;
    }

    public static double stdDev(int[] scores) {
        double mean = mean(scores);                    // mean() also checks the argument
        double squares = 0;
        for (int s : scores) {
            squares += (s - mean) * (s - mean);
        }
        return Math.sqrt(squares / scores.length);
    }

    public static String histogram(int[] scores) {
        check(scores);
        int[] buckets = new int[10];
        for (int s : scores) {
            buckets[Math.min(s / 10, 9)]++;            // 100 joins the 90-100 bucket
        }
        StringBuilder sb = new StringBuilder();
        for (int b = 0; b < 10; b++) {
            if (b > 0) {
                sb.append('\n');
            }
            sb.append(b * 10).append('-').append(b == 9 ? 100 : b * 10 + 9).append(" | ").append("#".repeat(buckets[b]));
        }
        return sb.toString();
    }

    private static void check(int[] scores) {
        Objects.requireNonNull(scores, "scores");
        if (scores.length == 0) {
            throw new IllegalArgumentException("no scores");
        }
        for (int s : scores) {
            if (s < 0 || s > 100) {
                throw new IllegalArgumentException("score out of range: " + s);
            }
        }
    }
}
```
