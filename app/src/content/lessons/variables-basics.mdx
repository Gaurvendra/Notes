## Why this matters

In dynamically typed languages, a typo such as assigning a string to a counter shows up as a crash in production, often
in the code path nobody tested. In Java the same mistake is a **compile error** on the developer's machine, seconds
after it's typed. That guarantee comes from two properties people often mix up, static and strong typing, and it
survives even when you let the compiler infer types with `var`. Good variable names are the other half: most of the
time spent on code is reading it, and a name is the cheapest documentation there is.

## TL;DR

<Callout type="tldr">
- A **variable** is a named storage location with a **type**: `int count = 1;` declares it, `count = 2;` assigns it.
- **Names** (identifiers) use letters, digits, `_` and `$`, can't start with a digit, can't be a keyword, and are
  case-sensitive. Convention: `camelCase` for variables, `UPPER_SNAKE_CASE` for constants.
- **Statically typed:** every variable's type is known at compile time. **Strongly typed:** the compiler only allows
  values compatible with that type, with no silent conversions that could lose information.
- **`var`** (Java 10) lets the compiler infer a local variable's type from its initialiser. It is still static typing:
  the type is fixed at compile time.
- Types are **primitive** (8: `byte short int long char float double boolean`) or **reference** (classes,
  interfaces, arrays). `String` is a class.
- `_` on its own is a keyword (Java 9); since Java 22 it means **"unnamed variable"**, for values you don't use.
</Callout>

## Mental model

A variable is a **labelled box** on a shelf:

- The **label** is the name (`count`).
- The **shape of the box** is the type (`int`): only values of that shape fit. A box shaped for whole numbers won't
  accept text, and the check happens when the shelf is built (compile time), not when someone tries to put something in.
- For a **primitive** type the box holds the value itself (the number 42). For a **reference** type the box holds a
  note saying where the object is.

Where the analogy breaks: a `var` box has no shape written on its label, but it still has one; the compiler measured
the first thing you put in and fixed the shape from then on.

## Concept, step by step

### 1. Declaring, initialising and assigning

Your notes define a variable as **a container that holds a value**, declared as `datatype name = value;`:

```java title="Declarations"
int count = 1;              // declare + initialise
boolean isActive = true;    // true is lower-case: True doesn't compile
double price;               // declare only…
price = 19.99;              // …assign later
count = count + 1;          // assign a new value: count is now 2
int width = 3, height = 4;  // several variables of one type (legal, but one per line reads better)
final int MAX_USERS = 100;  // final: can be assigned only once
```

Three words that are easy to blur:

| Term | Meaning | Example |
|---|---|---|
| **Declaration** | Introduces a name and its type | `double price;` |
| **Initialisation** | The first assignment, often in the declaration | `int count = 1;` |
| **Assignment** | Stores a new value in an existing variable | `count = 2;` |

A local variable must be **assigned before it's read**: `int x; System.out.println(x);` doesn't compile. (Fields get
default values instead; [Kinds of Variables](/lessons/variable-kinds/) explains the difference.)

### 2. Names: the rules

Your notes list the naming rules; here they are with the precise JLS details (§3.8):

| Rule | ✅ Legal | ❌ Illegal |
|---|---|---|
| Letters, digits, `_` and `$`, and letters from any alphabet (Unicode) | `count`, `total2`, `café`, `π` | `my-var` (`-` is minus), `first name` |
| Can't start with a digit | `item2` | `2item` |
| Can't be a keyword or the literals `true`, `false`, `null` | `className`, `newValue` | `class`, `new`, `null` |
| `_` on its own is a keyword (Java 9+) | `_count`, `x_1` | `int _ = 5;` before Java 22 (see step 5) |
| Case-sensitive | `total` and `Total` are two variables | |
| No length limit | `numberOfRetriesBeforeGivingUp` | |

`$` is legal, but by convention it's reserved for code generated by tools (compilers use it in names of nested and
synthetic classes, such as `Outer$Inner`); don't use it in your own names.

### 3. Names: the conventions

The compiler doesn't enforce these, but every Java code base follows them:

| Kind | Convention | Example |
|---|---|---|
| Local variables, fields, parameters, methods | `camelCase`, starting lower-case | `orderTotal`, `isActive`, `calculateTax()` |
| Constants (`static final` values that never change) | `UPPER_SNAKE_CASE` | `MAX_RETRIES`, `DEFAULT_TIMEOUT` |
| Classes, interfaces, records, enums | `PascalCase` | `OrderService`, `Runnable` |
| Packages | lower-case, reversed domain | `com.example.billing` |
| Booleans | read as a question | `isEmpty`, `hasNext`, `canRetry` |

Your notes' guidance, "small letters if it's one word, camelCase otherwise, and capitals for constants", is exactly
this. Choose names that say **what** a value means, not **how** it's stored: `elapsedDays`, not `d` or `intVal`.

### 4. Keywords

Keywords are words the language reserves; you can't use them as names. Java 25 has these **reserved keywords**:

```text title="Reserved keywords (JLS §3.9)"
abstract   assert     boolean    break      byte       case       catch      char
class      const      continue   default    do         double     else       enum
extends    final      finally    float      for        goto       if         implements
import     instanceof int        interface  long       native     new        package
private    protected  public     return     short      static     strictfp   super
switch     synchronized this     throw      throws     transient  try        void
volatile   while      _
```

- `const` and `goto` are reserved but **unused**: they exist so C programmers get an error rather than a surprise.
- `true`, `false` and `null` look like keywords but are **literals** (values). You still can't use them as names.
- **Contextual keywords** are special only in certain places, so they remain legal names elsewhere: `var`, `record`,
  `sealed`, `non-sealed`, `permits`, `yield`, `when`, `module`, `exports`, `requires`, `open`, `opens`, `provides`,
  `to`, `transitive`, `uses`, `with`. That's how Java added `var` (10) and `record` (16) without breaking old code
  that used them as variable names.

### 5. `_`: from a legal name to the unnamed variable

Sometimes a value must be declared but is never used: an exception you ignore, a loop counter you don't need. Since
**Java 22** (JEP 456) you name it `_`:

```java title="Unnamed variables (Java 22+)"
try {
    port = Integer.parseInt(text);
} catch (NumberFormatException _) {   // we don't need the exception object
    port = DEFAULT_PORT;
}

int count = 0;
for (String _ : lines) {              // count elements without using them
    count++;
}
```

`_` tells readers (and tools) the value is deliberately ignored. You can declare several `_` variables in the same
scope, and you can't read one. History: `_` was a legal name up to Java 7, deprecated with a warning in Java 8, a
keyword from Java 9 (so `int _ = 5;` stopped compiling), and it got this new meaning in Java 22.

### 6. Statically and strongly typed

Your notes say Java is **statically typed** ("we must define the datatype of a variable") and **strongly typed**
("there is a restriction on what value can be assigned"). Both are right, and they're different properties:

| | Static typing | Strong typing |
|---|---|---|
| Question it answers | *When* are types checked? | *How strictly* are types enforced? |
| Java's answer | At **compile time**: every variable and expression has a type the compiler knows | **Strictly**: no implicit conversion that could lose information, no treating one type as another |
| Opposite | Dynamic typing (Python, JavaScript): types checked at run time | Weak typing (C, JavaScript): implicit, sometimes surprising conversions |

What strong typing forbids, each of these is a compile error:

```java title="Rejected by the compiler"
int count = "5";          // error: incompatible types: String cannot be converted to int
boolean ok = 1;           // error: an int is not a boolean (legal in C)
int small = 3.7;          // error: possible lossy conversion from double to int
String s = 42;            // error: incompatible types: int cannot be converted to String
```

What it allows: **widening** conversions that can't lose the value's magnitude, such as `long total = count;`, and
explicit **casts** where you take responsibility, such as `int small = (int) 3.7;` (which gives 3).
[Type Conversion & Casting](/lessons/type-conversion/) covers every rule. Java also stays type-safe at run time: a
bad cast of an object throws `ClassCastException` instead of reinterpreting memory.

### 7. `var`: type inference, still static

Since **Java 10** (JEP 286) you can write `var` instead of the type of a **local variable**, and the compiler infers
the type from the initialiser:

```java title="var"
var count = 10;                            // int
var name = "Asha";                         // String
var prices = new ArrayList<Double>();      // ArrayList<Double>
var reader = Files.newBufferedReader(path); // BufferedReader: saves repeating a long type

count = "ten";   // error: incompatible types: String cannot be converted to int
```

The type is fixed at compile time: `var` saves typing, not checking. Its limits:

- Only for **local variables** with an initialiser, `for` loops and try-with-resources (and lambda parameters since
  Java 11). Not for fields, method parameters or return types.
- `var x;` and `var x = null;` don't compile: there's nothing to infer from.
- `var` infers the **exact** type of the initialiser: `var n = 10;` is `int`, not `long`;
  `var list = new ArrayList<>();` is `ArrayList<Object>`.
- Use it when the type is obvious from the right-hand side; spell the type out when it isn't.

### 8. The types: primitive and reference

Your notes draw the type tree: primitive types (char, byte, short, int, long as "integral"; float, double as
"fractional"; boolean) and reference types (class, interface, array, string). With the JLS's terms:

<TypeTree />

| Type | Size | Range | Field default | Literal |
|---|---|---|---|---|
| `byte` | 8 bits | −128 to 127 | `0` | `(byte) 10` |
| `short` | 16 bits | −32,768 to 32,767 | `0` | `(short) 10` |
| `int` | 32 bits | about ±2.1 billion (−2³¹ to 2³¹ − 1) | `0` | `10`, `1_000_000`, `0x1F`, `0b1010` |
| `long` | 64 bits | about ±9.2 × 10¹⁸ (−2⁶³ to 2⁶³ − 1) | `0L` | `10L` |
| `char` | 16 bits | 0 to 65,535 (a UTF-16 code unit) | `'\u0000'` | `'A'`, `'\n'`, `'é'` |
| `float` | 32 bits | about ±3.4 × 10³⁸, ~7 digits | `0.0f` | `1.5f` |
| `double` | 64 bits | about ±1.8 × 10³⁰⁸, ~15–17 digits | `0.0` | `1.5`, `2e-3` |
| `boolean` | not specified | `true`, `false` | `false` | `true` |

Two precise points about the notes' tree:

- **`char` is an integral type** in the JLS, not a separate category: it's an unsigned 16-bit number, and you can do
  arithmetic with it (`'A' + 1` is 66). [char & boolean](/lessons/char-and-boolean/) explains why it's UTF-16, not
  ASCII.
- **`String` is a class**, not a fifth kind of reference type. It's special only in having literals (`"hi"`) and the
  `+` operator. **Enums** and **records** are kinds of classes too.

Each primitive type gets its own lesson: [Integer Types](/lessons/integer-types/),
[char & boolean](/lessons/char-and-boolean/) and [Floating Point](/lessons/floating-point/).

## Scenarios

<Tabs>
<TabItem label="Real world: names that explain themselves">

```java title="Before"
int d;            // elapsed time in days
double r = 0.18;  // tax rate
boolean f = false;
List<int[]> l = new ArrayList<>();
```

```java title="After"
int elapsedDays;
static final double VAT_RATE = 0.18;
boolean isPaid = false;
List<Point> visitedPoints = new ArrayList<>();
```

The comments disappeared because the names say it. A reviewer reading `if (isPaid)` understands it; `if (f)` needs a
search. The constant is `static final` and in capitals, so everyone knows it never changes. (For money in real code,
use `BigDecimal`, not `double`: see [Floating Point](/lessons/floating-point/).)

</TabItem>
<TabItem label="Edge case: what var really infers">

```java title="VarInference.java"
import java.util.ArrayList;

public class VarInference {
    public static void main(String[] args) {
        var a = 10;
        var b = 10L;
        var c = 'A' + 1;
        var d = 1.0f * 2;
        var list = new ArrayList<>();
        list.add("text");
        list.add(42);

        System.out.println(((Object) a).getClass().getSimpleName());
        System.out.println(((Object) b).getClass().getSimpleName());
        System.out.println(((Object) c).getClass().getSimpleName());
        System.out.println(((Object) d).getClass().getSimpleName());
        System.out.println(list);
    }
}
```

```text output
Integer
Long
Integer
Float
[text, 42]
```

Casting to `Object` boxes each primitive, so `getClass()` shows its type: `a` is `int`, `b` is `long`, and `c` is
**`int`**, not `char`: `'A' + 1` is arithmetic, so the `char` is promoted to `int`. `d` is `float`, because a `float`
times an `int` is a `float`. With the diamond `<>` and no other clue, `var list` became an `ArrayList<Object>`, which
happily holds a `String` and an `Integer`: probably not what you meant. Write `new ArrayList<String>()` (or declare
`List<String> list`) when you use `var` with generics.

</TabItem>
<TabItem label="Anti-pattern → fix: magic numbers">

```java title="Anti-pattern"
if (attempts > 3) {
    Thread.sleep(86400000);
}
```

What is 3? What is 86,400,000? A later reader has to guess, and when the limit changes, someone must find every copy.

```java title="Fix: named constants"
static final int MAX_ATTEMPTS = 3;
static final Duration LOCKOUT = Duration.ofDays(1);

if (attempts > MAX_ATTEMPTS) {
    Thread.sleep(LOCKOUT.toMillis());
}
```

Constants get a name that says what they mean and a single place to change them. Using a type such as `Duration`
removes the unit guesswork too.

</TabItem>
</Tabs>

## Under the hood

<details>
<summary>What variables look like in bytecode</summary>

- **Local variables** don't exist by name at run time. `javac` assigns each one a numbered **slot** in the method's
  frame (`iload_1` reads slot 1). Names survive only in the optional `LocalVariableTable` debug attribute, which
  debuggers use; `javac -g` adds it.
- **`var` leaves no trace**: the class file records the inferred type, exactly as if you had written it. There's no
  run-time cost and no difference in the bytecode.
- **Fields** do keep their names and types in the class file (for example `count:I` for an `int` field), because other
  classes refer to them by name.
- **Strong typing at run time:** the bytecode verifier checks that instructions only use values of the right kind
  (`iadd` on two `int`s, never on a reference), and reference casts are checked by `checkcast`, which throws
  `ClassCastException` on a mismatch.
- A `boolean` has no instructions of its own: local `boolean` variables are stored as `int` 0 or 1 in their slot.

</details>

## Myths vs facts

<MythVsFact myth="A variable name can start with $, _ or a letter, so _ is a valid name." audit="4.4">
Names may contain and start with `$`, `_` or a letter, but **`_` on its own** has been a keyword since Java 9, and since
Java 22 it means the **unnamed variable** (for values you deliberately don't use). `$` is legal but reserved by
convention for generated code. Also, `true`, `false` and `null` are literals, not keywords, and words such as `var`,
`record` and `yield` are *contextual* keywords, still legal as variable names.
</MythVsFact>

<MythVsFact myth="With var, Java became dynamically typed." audit="4.2">
`var` is **type inference**: the compiler works out the type from the initialiser at compile time, and it can never
change. `var count = 10; count = "ten";` is a compile error. `var` only works for local variables.
</MythVsFact>

<MythVsFact myth="Reference types are class, interface, array and string." audit="4.5">
`String` is a **class**, not a separate kind of type. The JLS groups the primitives as **integral** (`byte`, `short`,
`int`, `long`, `char`) and **floating-point** (`float`, `double`), which together are the numeric types, plus `boolean`.
Reference types are class types (including enums and records), interface types, array types and type variables.
</MythVsFact>

<MythVsFact myth="Statically typed and strongly typed mean the same thing.">
**Static** is about *when* types are checked (compile time); **strong** is about *how strictly* (no implicit lossy or
unsafe conversions). C is statically but weakly typed; Python is dynamically but fairly strongly typed. Java is both
static and strong.
</MythVsFact>

## Doubts cleared

<FaqItem q="Why does `boolean myz = True;` not compile?">
The literals are lower-case: `true` and `false`. `True` would be a name, and there's no variable called `True`, so the
compiler reports "cannot find symbol". Java is case-sensitive everywhere.
</FaqItem>

<FaqItem q="Can I use `var` for a field or a method parameter?">
No. `var` is only for local variables (with an initialiser), `for`-loop variables, try-with-resources variables and
lambda parameters. Fields, parameters and return types are part of a class's API and must be written out.
</FaqItem>

<FaqItem q="Is `var` slower, or does it use `Object` under the hood?">
Neither. The compiler replaces `var` with the inferred type, so the bytecode is identical to writing the type yourself.
</FaqItem>

<FaqItem q="Can I name a variable `var`, `record` or `yield`?">
Yes: they're contextual keywords, so `int var = 1;` compiles (to keep old code working). You can't name a *class* `var`,
`record` or `yield` any more, and doing so for variables just confuses readers.
</FaqItem>

<FaqItem q="Can identifiers contain non-English letters?">
Yes. Identifiers are Unicode: `int café = 3;` and `double π = 3.14159;` are legal. Most teams stick to ASCII so everyone
can type the names; string *values* can hold any text regardless.
</FaqItem>

<FaqItem q="What happens if I declare a variable and never use it?">
It compiles (IDEs and linters warn). If it's a method's unused parameter, a caught exception or a loop variable you
must declare, name it `_` (Java 22+) to show it's intentional.
</FaqItem>

<FaqItem q="Why do constants use `static final` and capital letters?">
`final` means the variable can't be reassigned; `static` means one copy per class instead of one per object. Capital
names signal "this never changes", so readers don't look for assignments. If the constant is a primitive or a string
with a constant value, the compiler can even copy the value into the code that uses it.
</FaqItem>

<FaqItem q="Is `String` a primitive type?">
No, it's a class (`java.lang.String`), so a `String` variable holds a reference. It feels built in because it has
literals and `+`. Being a reference type is why comparing strings with `==` is a classic bug: see
[Strings](/lessons/strings/).
</FaqItem>

## Pitfalls and best practices

| ✅ Do | ❌ Don't |
|---|---|
| Name variables after what they mean: `elapsedDays` | Use `d`, `temp`, `data2`, `intVal` |
| Use `var` when the type is obvious from the right-hand side | Use `var` when the reader can't tell the type (`var x = process();`) |
| Give generic types with `var`: `new ArrayList<String>()` | Let `var` + `<>` infer `ArrayList<Object>` |
| Name ignored values `_` (Java 22+) | Name them `ignored`, `unused` or `e` and leave readers guessing |
| Replace magic numbers with named constants | Sprinkle `86400000` and `3` through the code |
| Declare variables close to first use, one per line | Declare everything at the top of a long method |
| Write `true`/`false` in lower-case, and types with the right case | Rely on case-insensitive habits from other languages |

## Senior lens

<Callout type="senior" title="Explain it to your team in 60 seconds">
"Java checks types at compile time, strictly, so a whole class of bugs never reaches production. `var` doesn't change
that: it's the compiler filling in a type we'd otherwise repeat. Our rule: use `var` when the right-hand side makes
the type obvious, and write the type when it carries information the reader needs. Names are our cheapest
documentation: a good name removes a comment, and a named constant removes a magic number."
</Callout>

**`var` in a team style guide**

| Situation | Guidance |
|---|---|
| `var user = new User(...)`, `var list = new ArrayList<Order>()` | ✅ Type is on the right-hand side |
| `var entry : map.entrySet()` with long generic types | ✅ Saves noise without hiding meaning |
| `var result = service.process(input)` | ⚠️ Prefer the explicit type unless the method name makes it obvious |
| Numeric literals where the type matters (`var total = 0;` for money in cents) | ❌ Write `long total = 0;` |
| Public API (fields, parameters, return types) | Not allowed by the language anyway |

**Code-review checklist**
- [ ] Names describe meaning; no single letters except loop indices and short lambdas.
- [ ] No magic numbers; constants are `static final` and `UPPER_SNAKE_CASE`.
- [ ] `var` is used only where the type is obvious, and never with a bare diamond `<>`.
- [ ] Intentionally unused variables are named `_` (Java 22+).

```java title="IdentifierCheck.java"
 */
public final class IdentifierCheck {

    static final Set<String> RESERVED = Set.of(
            "abstract", "assert", "boolean", "break", "byte", "case", "catch", "char", "class", "const", "continue",
            "default", "do", "double", "else", "enum", "extends", "final", "finally", "float", "for", "goto", "if",
            "implements", "import", "instanceof", "int", "interface", "long", "native", "new", "package", "private",
```

```java title="NamingStyle.java (solution)"
package track.variables_basics;

import java.util.ArrayList;
import java.util.List;
import java.util.Locale;

/** Reference solution for the NamingStyle exercise. */
public final class NamingStyle {

    private NamingStyle() {
    }

    public static List<String> words(String name) {
        List<String> words = new ArrayList<>();
        StringBuilder current = new StringBuilder();
        for (int i = 0; i < name.length(); i++) {
            char c = name.charAt(i);
            if (c == ' ' || c == '_' || c == '-') {
                flush(current, words);
                continue;
            }
            if (Character.isUpperCase(c) && current.length() > 0) {
                char prev = name.charAt(i - 1);
                boolean afterLowerOrDigit = Character.isLowerCase(prev) || Character.isDigit(prev);
                boolean endOfAcronym = Character.isUpperCase(prev)
                        && i + 1 < name.length() && Character.isLowerCase(name.charAt(i + 1));
                if (afterLowerOrDigit || endOfAcronym) {
                    flush(current, words);
                }
            }
            current.append(c);
        }
        flush(current, words);
        return words;
    }

    public static String toCamelCase(String name) {
        String pascal = toPascalCase(name);
        return pascal.isEmpty() ? pascal : Character.toLowerCase(pascal.charAt(0)) + pascal.substring(1);
    }

    public static String toPascalCase(String name) {
        StringBuilder out = new StringBuilder();
        for (String word : words(name)) {
            out.append(Character.toUpperCase(word.charAt(0))).append(word.substring(1));
        }
        return out.toString();
    }

    public static String toConstantCase(String name) {
        return String.join("_", words(name)).toUpperCase(Locale.ROOT);
    }

    private static void flush(StringBuilder current, List<String> words) {
        if (current.length() > 0) {
            words.add(current.toString().toLowerCase(Locale.ROOT));
            current.setLength(0);
        }
    }
}
```

```java title="VarTypeInference.java (solution)"
package track.variables_basics;

import java.util.ArrayList;
import java.util.List;

/** Reference solution for the VarTypeInference exercise (tokenise, then a two-level precedence parser). */
public final class VarTypeInference {

    private final List<String> tokens;
    private int pos;

    private VarTypeInference(List<String> tokens) {
        this.tokens = tokens;
    }

    public static String typeOf(String expression) {
        VarTypeInference parser = new VarTypeInference(tokenize(expression));
        String type = parser.expression();
        if (parser.pos != parser.tokens.size()) {
            throw new IllegalArgumentException("Unexpected token: " + parser.tokens.get(parser.pos));
        }
        return type;
    }

    /** expression = term (('+' | '-') term)* */
    private String expression() {
        String left = term();
        while (peekIs("+") || peekIs("-")) {
            String op = tokens.get(pos++);
            String right = term();
            if (op.equals("+") && (left.equals("String") || right.equals("String"))) {
                left = "String";
            } else {
                left = promote(left, right, op);
            }
        }
        return left;
    }

    /** term = literal (('*' | '/') literal)* */
    private String term() {
        String left = literal();
        while (peekIs("*") || peekIs("/")) {
            String op = tokens.get(pos++);
            left = promote(left, literal(), op);
        }
        return left;
    }

    private String literal() {
        if (pos >= tokens.size()) {
            throw new IllegalArgumentException("Missing operand");
        }
        String t = tokens.get(pos++);
        if (t.startsWith("\"")) {
            return "String";
        }
        if (t.startsWith("'")) {
            return "char";
        }
        if (t.equals("true") || t.equals("false")) {
            return "boolean";
        }
        if (t.matches("\\d+")) {
            return "int";
        }
        if (t.matches("\\d+[lL]")) {
            return "long";
        }
        if (t.matches("\\d+(\\.\\d+)?([eE]-?\\d+)?[fF]")) {
            return "float";
        }
        if (t.matches("\\d+(\\.\\d+)?([eE]-?\\d+)?[dD]?") && (t.contains(".") || t.matches(".*[eEdD].*"))) {
            return "double";
        }
        throw new IllegalArgumentException("Not an operand: " + t);
    }

    /** Binary numeric promotion (JLS §5.6), or a compile error for non-numeric operands. */
    private static String promote(String left, String right, String op) {
        if (!isNumeric(left) || !isNumeric(right)) {
            throw new IllegalArgumentException("Bad operand types for " + op + ": " + left + ", " + right);
        }
        for (String wide : List.of("double", "float", "long")) {
            if (left.equals(wide) || right.equals(wide)) {
                return wide;
            }
        }
        return "int";
    }

    private static boolean isNumeric(String type) {
        return List.of("int", "long", "float", "double", "char").contains(type);
    }

    private boolean peekIs(String s) {
        return pos < tokens.size() && tokens.get(pos).equals(s);
    }

    private static List<String> tokenize(String s) {
        List<String> tokens = new ArrayList<>();
        int i = 0;
        while (i < s.length()) {
            char c = s.charAt(i);
            if (c == ' ') {
                i++;
            } else if ("+-*/".indexOf(c) >= 0) {
                tokens.add(String.valueOf(c));
                i++;
            } else if (c == '"' || c == '\'') {
                int end = s.indexOf(c, i + 1);
                if (end < 0) {
                    throw new IllegalArgumentException("Unterminated literal");
                }
                tokens.add(s.substring(i, end + 1));
                i = end + 1;
            } else if (Character.isLetterOrDigit(c) || c == '.') {
                int start = i;
                while (i < s.length() && (Character.isLetterOrDigit(s.charAt(i)) || s.charAt(i) == '.'
                        || ((s.charAt(i) == '-') && (s.charAt(i - 1) == 'e' || s.charAt(i - 1) == 'E')
                                && Character.isDigit(s.charAt(start))))) {
                    i++;
                }
                tokens.add(s.substring(start, i));
            } else {
                throw new IllegalArgumentException("Unexpected character: " + c);
            }
        }
        if (tokens.isEmpty()) {
            throw new IllegalArgumentException("Empty expression");
        }
        return tokens;
    }
}
```

## Cheat sheet

<CheatSheet>

| Topic | Remember |
|---|---|
| **Declare / assign** | `int count = 1;` · `count = 2;` · locals must be assigned before use |
| **Legal names** | letters (Unicode), digits, `_`, `$`; not starting with a digit; not a keyword or `true`/`false`/`null`; case-sensitive |
| **`_`** | keyword since 9; **unnamed variable** since 22: `catch (Exception _)`, `for (var _ : list)` |
| **Conventions** | `camelCase` variables/methods · `PascalCase` types · `UPPER_SNAKE_CASE` constants · lower-case packages · `isX`/`hasX` booleans |
| **Keywords** | 51 reserved (incl. `const`, `goto` unused, and `_`); contextual: `var`, `record`, `sealed`, `permits`, `yield`, `when`… |
| **Static typing** | types checked at **compile time** |
| **Strong typing** | no implicit lossy/unsafe conversions: `int x = 3.7;` ✗, `boolean b = 1;` ✗ |
| **`var`** | local variables with an initialiser only; exact type inferred (`var n = 10` → `int`); `var` + `<>` → `Object` |
| **Primitives** | `byte` 8 · `short` 16 · `int` 32 · `long` 64 · `char` 16 unsigned · `float` 32 · `double` 64 · `boolean` |
| **Groups (JLS)** | integral = `byte short int long char`; floating-point = `float double`; + `boolean` |
| **Reference types** | classes (incl. `String`, enums, records), interfaces, arrays, type variables |
