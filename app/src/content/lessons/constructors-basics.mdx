## Why this matters

A developer adds `public Customer(String id)` to a class that had no constructor. Their own code compiles after a few
fixes, but the release breaks elsewhere: a subclass no longer compiles, and a framework that creates customers through
a no-argument constructor (a JPA provider, a JSON mapper) fails at run time, because the constructor the compiler used
to add has silently disappeared. Constructors decide which objects can exist at all. Knowing exactly what they do, and
what the compiler does for you, is how you make invalid objects impossible instead of merely unlikely.

## TL;DR

<Callout type="tldr">
- A **constructor** initialises a new object. It has the class's name and **no return type**, and runs after `new` has
  allocated the object and set every field to its default value (`0`, `false`, `null`).
- The constructor doesn't create the object or return it: **`new` does**. A "constructor" with a return type is just a
  method that happens to have the class's name.
- Constructors aren't methods and aren't inherited. They can be `public`, `protected`, package-private or `private`, but
  never `static`, `final`, `abstract`, `synchronized` or `native`.
- Interfaces have no constructors; **abstract classes do** (subclasses run them through `super(...)`).
- No constructor written → the compiler adds the **default constructor**: no parameters, the class's access,
  body `super();`. It doesn't set default values; they're already there. Declare **any** constructor and it's gone.
- Kinds: no-argument, parameterised, overloaded, copy constructors; records add canonical and compact constructors;
  enum constructors are always private.
- A constructor's real job: establish the class's invariants, so every object is valid from the moment `new` returns.
</Callout>

## Mental model

Think of `new Dog("Rex", 3)` as a production line with two stations. At the first, the JVM builds a **blank** Dog:
memory for every field, each set to zero, `false` or `null`. At the second, your constructor receives that blank
object as `this` and fills it in. The constructor never builds anything from scratch, and it never hands anything
back: the line itself delivers the finished object to whoever wrote `new`.

Where the picture breaks: the blank object isn't hidden while it's being filled in. Code running inside the
constructor (or a superclass constructor) can see half-initialised fields, which is the subject of the next lesson.

## Concept, step by step

### 1. What a constructor is

The notes (08 p6) define it well: it's used to create an instance, that is, to initialise its instance variables. It
looks like a method except that its **name is the class's name** and it has **no return type**, and the `new` keyword
is what calls it. Precisely (JLS §8.8): `new` creates the object; the constructor **initialises** it.

```java title="Rectangle.java"
public class Rectangle {
    private final double width;
    private final double height;

    public Rectangle(double width, double height) {
        if (width <= 0 || height <= 0) {
            throw new IllegalArgumentException("sides must be positive");
        }
        this.width = width;
        this.height = height;
    }

    public double area() {
        return width * height;
    }

    public static void main(String[] args) {
        Rectangle r = new Rectangle(3, 4);
        System.out.println(r.area());
        try {
            new Rectangle(0, 4);
        } catch (IllegalArgumentException e) {
            System.out.println("rejected: " + e.getMessage());
        }
    }
}
```

```text output
12.0
rejected: sides must be positive
```

Constructors are **not methods** and **not members** of the class. They're never inherited, so a `Square extends
Rectangle` doesn't get `Square(double, double)` for free. You can't call one like a method (`r.Rectangle(1, 2)` doesn't
exist); only `new`, `this(...)` and `super(...)` invoke constructors (and reflection's `Constructor.newInstance`).

### 2. No return type: what the notes get wrong

The notes answer "why is there no return type?" with "because implicitly Java adds the class as the return type". That's
a common myth (audit 8.2). A constructor returns **nothing**. In the class file it's a special method named `<init>`
whose return type is `void`, and the reference comes from the `new` expression. `new Dog("Rex", 3)` compiles to roughly
this (`javap -c`, constant-pool numbers left out):

```text title="javap -c (simplified)"
new           Dog                              // allocate; fields get default values
dup                                            // keep a second copy of the reference
ldc           "Rex"
iconst_3
invokespecial Dog."<init>":(Ljava/lang/String;I)V   // run the constructor; V = void
astore_1                                       // the remaining copy is the value of new
```

The `dup` is the giveaway: the constructor consumes one copy of the reference as `this` and returns nothing, and the
other copy, which `new` produced, is what gets stored in the variable.

The notes' other point is right: you **can** write a method with the class's name and a return type, and it's then an
ordinary method, not a constructor:

```java title="Counter.java"
public class Counter {
    int count;

    void Counter() {                       // a method named Counter, not a constructor
        count = 5;
    }

    public static void main(String[] args) {
        Counter c = new Counter();         // the default constructor runs
        System.out.println(c.count);
        c.Counter();                       // an ordinary method call
        System.out.println(c.count);
    }
}
```

```text output
0
5
```

### 3. Which modifiers, and why not the others

The notes explain why a constructor can't be `static`, `final`, `abstract` or `synchronized`; their reasons hold
(audit 8.3). The JLS allows only the access modifiers (§8.8.3):

| Modifier | Allowed? | Why |
|---|---|---|
| `public`, `protected`, `private`, none | Yes | Who may create objects this way |
| `static` | No | A constructor works on one specific new object, `this`; static code has no `this` (and couldn't chain with `super(...)`) |
| `final` | No | `final` stops overriding, and constructors are never inherited, so there's nothing to stop |
| `abstract` | No | `abstract` means "a subclass provides the body"; constructors aren't inherited, and every constructor needs a body |
| `synchronized` | No | It would lock an object that other threads normally can't see until construction is over (JLS §8.8.3); lock inside if you must |
| `native` | No | A design choice that lets the JVM verify that every object's superclass constructors really run (JLS §8.8.3) |

### 4. Interfaces have no constructors; abstract classes do

The notes are right that an interface can't have a constructor (audit 8.4): it has no instance state to initialise
and can't be instantiated. (`new Runnable() { ... }` creates an object of an **anonymous class** that implements the
interface: [Nested & Anonymous Classes](/lessons/nested-and-anonymous-classes/).)

**Abstract classes do have constructors**, even though you can't write `new Shape()`. They run when a subclass object is
created, through the subclass constructor's `super(...)` call, and they initialise the abstract class's part of the
object:

```java title="Shapes.java"
public class Shapes {
    abstract static class Shape {
        private final String name;

        protected Shape(String name) {           // runs for every subclass object
            this.name = name;
            System.out.println("Shape(" + name + ")");
        }

        String name() {
            return name;
        }

        abstract double area();
    }

    static class Square extends Shape {
        private final double side;

        Square(double side) {
            super("square");                     // calls Shape(String)
            this.side = side;
        }

        @Override
        double area() {
            return side * side;
        }
    }

    public static void main(String[] args) {
        Shape s = new Square(2);
        System.out.println(s.name() + " " + s.area());
    }
}
```

```text output
Shape(square)
square 4.0
```

`protected` is the usual choice for an abstract class's constructors: only subclasses can call them anyway
([Abstract Classes](/lessons/abstract-classes/)).

### 5. The default constructor

If a class declares **no** constructor at all, the compiler adds one (JLS §8.8.9): no parameters, the same access as
the class, and a body that only calls `super()`. The notes add that it "also sets default values for all instance
variables", which is a myth (audit 8.5): fields get their default values **when the object is allocated**, before any
constructor runs, with or without a default constructor. You saw it in the stepper above: `name` was `null` and `age`
was `0` before the first line of the constructor.

The important consequence is the one the notes state: the default constructor is added **only when no constructor is
declared**. Declare one, and it's gone:

<DefaultConstructorRule />

```java title="Customers.java"
class Customer {
    final String id;

    Customer(String id) {
        this.id = id;
    }
}

class Vip extends Customer {
    Vip(String id) {
        super(id);                  // without this constructor, Vip wouldn't compile
    }
}

public class Customers {
    public static void main(String[] args) {
        // new Customer();          error: constructor Customer in class Customer cannot be applied to given types
        System.out.println(new Vip("c-42").id);
    }
}
```

```text output
c-42
```

If code (or a framework) needs `new Customer()`, declare the no-argument constructor yourself. A **no-argument
constructor** that you write is exactly what the notes call it: like the default one, but declared by you, so it can
do work and have the access you choose.

### 6. Kinds of constructors

The notes list default, no-argument, parameterised, overloaded and private constructors (08 p7-8). In one class:

```java title="Point.java"
public class Point {
    private final int x;
    private final int y;

    public Point() {                        // no-argument
        this(0, 0);
    }

    public Point(int x, int y) {            // parameterised
        this.x = x;
        this.y = y;
    }

    public Point(Point other) {             // copy constructor
        this(other.x, other.y);
    }

    @Override
    public String toString() {
        return "(" + x + ", " + y + ")";
    }

    public static void main(String[] args) {
        Point origin = new Point();
        Point p = new Point(3, 4);
        Point copy = new Point(p);
        System.out.println(origin + " " + p + " " + copy + " " + (copy == p));
    }
}
```

```text output
(0, 0) (3, 4) (3, 4) false
```

- **Overloaded constructors** are chosen by the same rules as overloaded methods
  ([Overloading](/lessons/overloading-resolution/)). `this(...)` hands over to another constructor of the same class;
  [Constructor Chaining & Init Order](/lessons/constructor-chaining-init-order/) covers it in depth.
- **Parameterised constructors** don't have to set every field: as the notes say, the others keep their default values.
- A **copy constructor** takes an object of the same class and copies its state; it's clearer and safer than `clone()`
  ([The Object Class Contracts](/lessons/object-class-contracts/)).
- **Private constructors** stop other classes from calling `new`, for utility classes, singletons and static factory
  methods: the subject of [Private Constructors & Static Factories](/lessons/private-constructors-static-factories/).
- **Records** get a canonical constructor with one parameter per component, and can declare a **compact**
  constructor that only validates: `record Range(int lo, int hi) { Range { if (lo > hi) throw new
  IllegalArgumentException(); } }` ([Records & Pattern Matching](/lessons/records-and-pattern-matching/)).
- **Enum** constructors are always private: only the constants may create instances. Writing `public` is a compile
  error ("modifier public not allowed here", verified) ([Enums in Depth](/lessons/enums/)).

### 7. A constructor's real job: invariants

An **invariant** is a rule that's true for every object of the class at all times: a rectangle's sides are positive, an
email address contains exactly one `@`. The constructor is the one place where every object passes, so it's where the
rules are established:

- **Validate, then assign.** Reject bad arguments with an exception before the object can be used
  (`Objects.requireNonNull`, `IllegalArgumentException`). An object that never exists in an invalid state can't cause
  trouble later.
- **Normalise.** Store values in one canonical form (lower-case emails, fractions in lowest terms), so equal objects have
  equal fields.
- **Copy what you don't own.** Store copies of mutable arguments ([Pass-by-Value](/lessons/pass-by-value/)).
- **Do little else.** No I/O, no thread starts, no calls to overridable methods, no leaking `this` (next lesson).

```java title="Email.java"
import java.util.Locale;
import java.util.Objects;

public final class Email {
    private final String address;

    public Email(String address) {
        Objects.requireNonNull(address, "address");
        int at = address.indexOf('@');
        if (at <= 0 || at != address.lastIndexOf('@') || at == address.length() - 1) {
            throw new IllegalArgumentException("not an email address: " + address);
        }
        this.address = address.toLowerCase(Locale.ROOT);    // normalised
    }

    @Override
    public String toString() {
        return address;
    }

    public static void main(String[] args) {
        System.out.println(new Email("Ann@Example.COM"));
        try {
            new Email("ann.example.com");
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

```text output
ann@example.com
not an email address: ann.example.com
```

## Scenarios

<Tabs>
<TabItem label="Real world: a framework needs a no-argument constructor">

```java title="Customer.java (a JPA entity)"
@Entity
public class Customer {
    @Id
    private String id;
    private String name;

    protected Customer() {               // for the framework only
    }

    public Customer(String id, String name) {
        this.id = Objects.requireNonNull(id);
        this.name = Objects.requireNonNull(name);
    }
}
```

Frameworks that load objects from a database or JSON often create them reflectively with a no-argument constructor,
then fill in the fields. The JPA specification requires entities to have a public or protected no-argument
constructor. Declaring `Customer(String, String)` removes the default one, so it has to be written back explicitly.
Making it `protected` keeps application code on the validating constructor. (Many JSON libraries can also use a
constructor with parameters, or a record's canonical constructor, when configured to.)

</TabItem>
<TabItem label="Edge case: the parameter that hides the field">

```java title="Box.java"
public class Box {
    int size;

    Box(int size) {
        size = size;                    // assigns the parameter to itself
    }

    public static void main(String[] args) {
        System.out.println(new Box(7).size);
    }
}
```

```text output
0
```

Inside the constructor, `size` means the **parameter**, which hides the field with the same name. `size = size;` copies
the parameter into itself, and the field keeps its default value. Write `this.size = size;`. Making the field `final`
turns the mistake into a compile error, because a blank final field must be assigned in every constructor.

</TabItem>
<TabItem label="Anti-pattern → fix: telescoping constructors">

```java title="Anti-pattern"
public class Pizza {
    public Pizza(int size) { ... }
    public Pizza(int size, boolean cheese) { ... }
    public Pizza(int size, boolean cheese, boolean ham) { ... }
    public Pizza(int size, boolean cheese, boolean ham, boolean olives) { ... }
}
// new Pizza(30, true, false, true): which flag is which?
```

Each new option adds a constructor, and call sites become rows of unlabelled booleans that are easy to get wrong.
When there are many optional parameters, give the class a **builder** (Effective Java, item 2), and keep one private
constructor that validates the complete set:

```java title="Fix"
public final class Pizza {
    private final int size;
    private final boolean cheese;
    private final boolean ham;
    private final boolean olives;

    private Pizza(Builder b) {
        if (b.size <= 0) {
            throw new IllegalArgumentException("size");
        }
        size = b.size;
        cheese = b.cheese;
        ham = b.ham;
        olives = b.olives;
    }

    public static Builder ofSize(int size) {
        return new Builder(size);
    }

    public static final class Builder {
        private final int size;
        private boolean cheese;
        private boolean ham;
        private boolean olives;

        private Builder(int size) {
            this.size = size;
        }

        public Builder cheese() {
            cheese = true;
            return this;
        }

        public Builder ham() {
            ham = true;
            return this;
        }

        public Builder olives() {
            olives = true;
            return this;
        }

        public Pizza build() {
            return new Pizza(this);
        }
    }
}
// Pizza.ofSize(30).cheese().olives().build()
```

</TabItem>
</Tabs>

## Under the hood

<details>
<summary>Constructors in the class file and the JVM</summary>

- **`<init>` methods.** Each constructor compiles to a method named `<init>` with a `void` descriptor. A class's static
  initialisation compiles to `<clinit>`. Neither name is legal in Java source, which is why you can't call them like
  methods.
- **An uninitialised object can't be used.** The bytecode verifier tracks the result of `new` as a special
  "uninitialised" type until `invokespecial <init>` has been called on it, and rejects code that uses it before then:
  you can't call a method on it, pass it to one or store it in a field until its constructor has run.
- **Every constructor calls another constructor** of the same class or of the superclass (`Object()` at the top); the
  verifier checks this too. The compiler inserts `super()` when you don't write a call
  ([Constructor Chaining & Init Order](/lessons/constructor-chaining-init-order/)).
- **Reflection.** `Class.getConstructors()` lists the public constructors; `getDeclaredConstructor(String.class,
  int.class)` finds one by parameter types; `newInstance(...)` calls it. `Class.newInstance()` is deprecated since
  Java 9 because it could throw checked exceptions without declaring them
  ([Reflection Basics](/lessons/reflection-basics/)).

</details>

## Myths vs facts

<MythVsFact myth="A constructor has no return type because Java implicitly returns the class type." audit="8.2">
A constructor returns nothing: in the class file it's `<init>` with a `void` descriptor. The `new` expression creates
the object and produces the reference; the constructor only initialises the object it's given as `this`.
</MythVsFact>

<MythVsFact myth="The default constructor sets the fields to their default values." audit="8.5">
Fields get their default values when the object is allocated, before any constructor runs, whether or not there's a
default constructor. The default constructor only calls `super()`.
</MythVsFact>

<MythVsFact myth="Every class has a no-argument constructor." audit="8.5">
Only a class that declares no constructor gets one from the compiler. Declare `Customer(String id)` and `new
Customer()` stops compiling, along with subclasses that relied on the implicit `super()`.
</MythVsFact>

<MythVsFact myth="Abstract classes can't have constructors, because they can't be instantiated." audit="8.4">
They can, and usually should when they have fields: the constructor runs through `super(...)` whenever a subclass
object is created, and initialises the abstract class's part of it.
</MythVsFact>

<MythVsFact myth="The constructor creates the object." audit="8.1">
`new` creates it (allocation, default values); the constructor initialises it. By the time your constructor's first
line runs, the object already exists.
</MythVsFact>

## Doubts cleared

<FaqItem q="What's the difference between the default constructor and a no-argument constructor?">
The default constructor is the one the compiler adds when you declare none: no parameters, the class's access, body
`super();`. A no-argument constructor is one you write: it can have a body, any access, and it exists even if other
constructors exist too.
</FaqItem>

<FaqItem q="What happens to fields that the constructor doesn't assign?">
They keep their default values from allocation: `0`, `0.0`, `false`, `'\u0000'` or `null`. A `final` field is the
exception: it must be assigned in every constructor, or the class doesn't compile.
</FaqItem>

<FaqItem q="Can a constructor throw an exception?">
Yes, unchecked or checked (declared with `throws`, like a method). Then `new` completes abruptly and no reference is
returned, which is the right way to reject bad arguments.
</FaqItem>

<FaqItem q="Can a constructor contain a return statement?">
Only `return;` without a value, to finish early. `return something;` doesn't compile: there's no return type.
</FaqItem>

<FaqItem q="Can a constructor call methods of its own class?">
Yes. Private, static and final methods are safe. Calling a method a subclass can override is risky: it can run before
the subclass's fields are initialised ([Constructor Chaining & Init Order](/lessons/constructor-chaining-init-order/)).
</FaqItem>

<FaqItem q="Are constructors inherited?">
No. A subclass declares its own constructors and calls a superclass constructor from each of them with `super(...)`
(the compiler inserts `super()` when you don't).
</FaqItem>

<FaqItem q="Why can't an enum's constructor be public?">
An enum's instances are exactly its constants; nobody else may create one. So enum constructors are implicitly
private, and `public` or `protected` is a compile error.
</FaqItem>

<FaqItem q="Does a record have a constructor?">
Yes: a canonical constructor with one parameter per component, generated unless you write it. A compact constructor
(`Range { ... }`, without a parameter list) lets you validate or normalise the arguments before the fields are assigned.
</FaqItem>

<FaqItem q="Should a constructor do expensive work, like reading a file?">
Usually not. It makes objects slow and hard to test, and failures surface in odd places. Pass already-loaded data in,
or use a static factory method that does the work and then calls a simple constructor.
</FaqItem>

## Pitfalls and best practices

| ✅ Do | ❌ Don't |
|---|---|
| Validate and normalise arguments before assigning fields | Let invalid objects be created and fail later |
| Use `this.field = field` when a parameter has the field's name | Write `field = field` |
| Make fields `final` so every constructor must assign them | Leave fields that never change reassignable |
| Declare the no-argument constructor explicitly when code or frameworks need it | Rely on the default constructor in a class that may gain constructors |
| Give abstract classes `protected` constructors that initialise their state | Assume abstract classes don't need constructors |
| Use builders or static factories for many optional parameters | Add a constructor per combination of options |
| Keep constructors light | Do I/O, start threads or call overridable methods in them |

## Senior lens

<Callout type="senior" title="Explain it to your team in 60 seconds">
"`new` allocates the object with default values, then the constructor initialises it; the constructor returns nothing.
That makes the constructor the one gate every object passes through, so it's where invariants are established:
validate, normalise, copy what we don't own, assign final fields. The compiler only gives us a default constructor if
we write none, and it disappears the moment we add one, so frameworks that need a no-argument constructor get an
explicit protected one."
</Callout>

**Where constructors go wrong in production**

| Symptom | Cause | Fix |
|---|---|---|
| A framework can't instantiate a class after a change | A new constructor removed the default one | Declare a `protected` no-argument constructor |
| Subclasses stop compiling after a superclass change | The implicit `super()` has no constructor to call | Call `super(args)` explicitly |
| Invalid objects discovered far from where they were made | Constructors that don't validate | Validate at construction; fail fast |
| Fields that are unexpectedly 0 or null | `field = field` shadowing, or a skipped assignment | `this.field = field`; `final` fields |
| Slow, flaky tests | Constructors doing I/O or starting threads | Inject dependencies; move work to factories |
| Unreadable `new X(true, false, 3, null)` call sites | Telescoping constructors | Builders, static factories, records |

Dependency-injection frameworks such as Spring favour **constructor injection**: the dependencies are the constructor's
parameters, so they can be `final`, the object is complete as soon as it's created, and a test can build one with
`new` (exercise `Container` builds a tiny version).

**Code-review checklist**
- [ ] Every constructor leaves the object valid: arguments checked, fields assigned, mutable inputs copied.
- [ ] Fields that don't change are `final`.
- [ ] Classes used by frameworks keep the no-argument constructor they need, with the narrowest access.
- [ ] No overridable calls, I/O or `this` leaks in constructors.
- [ ] Many optional parameters use a builder or factories, not a stack of constructors.

## Modern Java

- <VersionBadge since={9} /> `Class.newInstance()` deprecated; use `getDeclaredConstructor().newInstance()`.
- <VersionBadge since={16} jep={395} /> Records: generated canonical constructors and compact constructors for
  validation.
- <VersionBadge since={25} jep={513} /> Flexible constructor bodies: statements, such as argument checks, may come
  before `super(...)` or `this(...)` ([Constructor Chaining & Init Order](/lessons/constructor-chaining-init-order/)).
- <VersionBadge since={26} jep={500} /> Warnings when deep reflection changes `final` fields, which some frameworks did
  after creating an object with a no-argument constructor: one more reason to initialise objects through constructors
  (records, constructor-based mapping). JDK 27 brings nothing new for constructors.

package track.constructors_basics;

/** Reference solution for the Fraction exercise. */
public final class Fraction {
    private final int numerator;
    private final int denominator;

    public Fraction(int numerator, int denominator) {
        this(normalised(numerator, denominator));
    }

    public Fraction(int whole) {
        this(whole, 1);
    }

    public Fraction(String text) {
        this(parse(text));
    }

    /** Every constructor ends here, with an already normalised pair. */
    private Fraction(int[] parts) {
        this.numerator = parts[0];
        this.denominator = parts[1];
    }

    private static int[] normalised(long n, long d) {
        if (d == 0) {
            throw new ArithmeticException("zero denominator");
        }
        if (d < 0) {
            n = -n;                                   // safe in long, even for Integer.MIN_VALUE
            d = -d;
        }
        long g = gcd(Math.abs(n), d);
        n /= g;
        d /= g;
        if (n != (int) n || d != (int) d) {
            throw new ArithmeticException("doesn't fit in int: " + n + "/" + d);
        }
        return new int[] {(int) n, (int) d};
    }

    private static long gcd(long a, long b) {
        while (b != 0) {
            long t = a % b;
            a = b;
            b = t;
        }
        return a;
    }

    private static int[] parse(String text) {
        String s = text.trim();                       // NullPointerException for null
        int slash = s.indexOf('/');
        if (slash < 0) {
            return normalised(Integer.parseInt(s), 1);
        }
        if (s.indexOf('/', slash + 1) >= 0) {
            throw new NumberFormatException("more than one '/': " + text);
        }
        int n = Integer.parseInt(s.substring(0, slash).trim());
        int d = Integer.parseInt(s.substring(slash + 1).trim());
        return normalised(n, d);
    }

    public int numerator() {
        return numerator;
    }

    public int denominator() {
        return denominator;
    }

    public Fraction plus(Fraction other) {
        long n = (long) numerator * other.denominator + (long) other.numerator * denominator;
        return new Fraction(normalised(n, (long) denominator * other.denominator));
    }

    public Fraction times(Fraction other) {
        long n = (long) numerator * other.numerator;
        return new Fraction(normalised(n, (long) denominator * other.denominator));
    }

    @Override
    public boolean equals(Object o) {
        return o instanceof Fraction f && f.numerator == numerator && f.denominator == denominator;
    }

    @Override
    public int hashCode() {
        return 31 * numerator + denominator;
    }

    @Override
    public String toString() {
        return denominator == 1 ? Integer.toString(numerator) : numerator + "/" + denominator;
    }
}

import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;
import java.util.Objects;

/** Reference solution for the Container exercise. */
public final class Container {
    private final Map<Class<?>, Class<?>> bindings = new HashMap<>();
    private final Map<Class<?>, Object> instances = new HashMap<>();
    private final LinkedHashSet<Class<?>> creating = new LinkedHashSet<>();   // the path being built, in order

    public <T> void bind(Class<T> type, Class<? extends T> implementation) {
        bindings.put(Objects.requireNonNull(type), Objects.requireNonNull(implementation));
    }

    public <T> void instance(Class<T> type, T value) {
        instances.put(Objects.requireNonNull(type), Objects.requireNonNull(value));
    }

    public <T> T get(Class<T> type) {
        return type.cast(resolve(type));
    }

    private Object resolve(Class<?> type) {
        Object known = instances.get(type);
        if (known != null) {
            return known;
        }
        Class<?> implementation = bindings.getOrDefault(type, type);
        known = instances.get(implementation);
        if (known == null) {
            known = create(implementation);
            instances.put(implementation, known);
        }
        instances.put(type, known);                    // a bound type shares its implementation's instance
        return known;
    }

    private Object create(Class<?> type) {
        if (type.isPrimitive()) {
            throw new IllegalStateException("can't inject a primitive: " + type.getName());
        }
        if (type.isInterface() || Modifier.isAbstract(type.getModifiers())) {
            throw new IllegalStateException("no binding for " + type.getSimpleName());
        }
        if (!creating.add(type)) {
            List<String> path = new ArrayList<>();
            boolean inCycle = false;
            for (Class<?> c : creating) {
                inCycle |= c == type;
                if (inCycle) {
                    path.add(c.getSimpleName());
                }
            }
            path.add(type.getSimpleName());
            throw new IllegalStateException("dependency cycle: " + String.join(" -> ", path));
        }
        try {
            Constructor<?>[] constructors = type.getConstructors();
            if (constructors.length != 1) {
                throw new IllegalStateException(type.getSimpleName() + " needs exactly one public constructor, has "
                        + constructors.length);
            }
            Class<?>[] parameters = constructors[0].getParameterTypes();
            Object[] args = new Object[parameters.length];
            for (int i = 0; i < parameters.length; i++) {
                if (parameters[i].isPrimitive()) {
                    throw new IllegalStateException(type.getSimpleName() + " has a primitive parameter: " + parameters[i]);
                }
                args[i] = resolve(parameters[i]);
            }
            return constructors[0].newInstance(args);
        } catch (InvocationTargetException e) {
            Throwable cause = e.getCause();
            if (cause instanceof RuntimeException unchecked) {
                throw unchecked;
            }
            if (cause instanceof Error error) {
                throw error;
            }
            throw new IllegalStateException("the constructor of " + type.getSimpleName() + " failed", cause);
        } catch (InstantiationException | IllegalAccessException e) {
            throw new IllegalStateException("can't create " + type.getSimpleName(), e);
        } finally {
            creating.remove(type);
        }
    }
}

## Cheat sheet

<CheatSheet>

| Topic | Remember |
|---|---|
| **What** | Same name as the class, no return type; initialises the object `new` created |
| **Order** | `new` allocates (fields = 0/false/null) → constructor runs on `this` → `new` returns the reference |
| **Not a method** | Not inherited, not callable like a method; `<init>` with a `void` descriptor in bytecode |
| **Modifiers** | `public`/`protected`/package/`private` only; never `static`, `final`, `abstract`, `synchronized`, `native` |
| **Interfaces vs abstract classes** | Interfaces: none. Abstract classes: yes, run via `super(...)` |
| **Default constructor** | Only if you declare none: no parameters, class's access, `super();`; doesn't set defaults |
| **Gotcha** | Declaring any constructor removes the default one (`new X()` and subclasses break) |
| **Kinds** | No-arg, parameterised, overloaded, copy, private; records: canonical/compact; enums: private |
| **Shadowing** | `this.size = size;` (not `size = size;`) |
| **Job** | Validate, normalise, copy mutable inputs, assign final fields; keep it light |

</CheatSheet>
