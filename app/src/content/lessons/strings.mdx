## Why this matters

An access check reads `if (role == "admin")`. Every unit test passes, because the tests pass the literal `"admin"`.
In production, the role comes from a database or an HTTP header, and the check silently fails for real
administrators, or, in the mirror-image bug, a different check succeeds when it shouldn't. Strings are everywhere in
Java programs (identifiers, messages, JSON, SQL, keys in maps), and they behave differently from every other object in
three ways: the language has literals for them, equal literals are **shared** in a pool, and they can **never
change**. Those three facts explain the classic interview questions (`==` vs `equals`, "how many objects does
`new String("hello")` create?", why `+` in a loop is slow) and a good share of production bugs.

## TL;DR

<Callout type="tldr">
- `String` is a final class holding an **immutable** sequence of UTF-16 `char` values. Methods like `toUpperCase`
  return a **new** string; the original never changes.
- String **literals** refer to shared objects in the **String Constant Pool**, which is part of the heap (since
  Java 7). Equal literals, and compile-time constant expressions like `"hel" + "lo"`, give the **same** object.
- `==` compares references, `equals` compares characters. Always use `equals` (or `Objects.equals`) for text.
- `new String("hello")` always creates a new object outside the pool; `intern()` returns the pooled instance.
- Building text in a loop with `+=` copies everything each time (quadratic); use `StringBuilder`, `String.join` or
  `Collectors.joining`. A single `a + b + c` expression is fine.
- Traps: `split` takes a **regex** and drops trailing empty strings, `length()` counts UTF-16 units (an emoji is 2),
  and case conversion depends on the locale. Text blocks (`"""`) make multi-line strings readable.
</Callout>

## Mental model

A `String` is a **printed label**: once printed, the text on it can't be edited. "Changing" a string means printing a
new label and moving your variable to it; anyone else holding the old label still sees the old text, which is why
sharing labels is perfectly safe. The **pool** is a rack of pre-printed labels for every literal in your code: when
two parts of a program write the same literal, they're handed the same label from the rack instead of two copies.

A `StringBuilder` is the opposite: a **whiteboard** you keep writing on, with room to spare. You edit it freely and,
when you're done, print one label from it with `toString()`.

## Concept, step by step

### 1. Strings are immutable objects

`String` is a class (not a primitive), declared `final`, and none of its methods changes the characters it holds
(JLS §4.3.3). Every method that seems to modify a string returns a new one:

```java title="Immutable.java"
public class Immutable {
    public static void main(String[] args) {
        String name = "java";
        name.toUpperCase();                 // a new String is created and thrown away: name is unchanged
        System.out.println(name);
        String upper = name.toUpperCase();  // keep the result
        name = name + " 25";                // re-points the variable to a new String
        System.out.println(upper + " " + name);
    }
}
```

```text output
java
JAVA java 25
```

The **object** can't change, but the **variable** can be re-pointed (unless it's `final`). Immutability is a design
choice with big payoffs:

- **Safe sharing**: any number of variables, threads and data structures can hold the same string without copies or
  locks.
- **Security**: a file name, URL or class name that has been checked can't be changed afterwards by someone who still
  holds a reference to it.
- **Pooling**: sharing one object per literal is only safe because nobody can change it.
- **Fast hashing**: the hash code is computed on first use and cached in the object, which makes strings ideal keys
  for `HashMap`.

### 2. Literals and the String Constant Pool

The notes: "Inside heap, there is a fixed memory space called the String Constant Pool", and two variables
initialised with the same literal hold references to the same object. More precisely (JLS §3.10.5), a string literal
always refers to the same `String` instance, and so do string-valued **constant expressions**, such as
`"hel" + "lo"`, which the compiler evaluates itself. The pool has been part of the heap since Java 7 (before that it
lived in PermGen, which Java 8 removed).

Step through the classic cases. The key results (a literal vs a constant expression, vs a run-time concatenation, vs
`intern()`) were checked on a real JVM:

<MemoryStepper trace="string-pool" />

What gets pooled automatically:

| Expression | Pooled? | Why |
|---|---|---|
| `"hello"` | Yes | A literal |
| `"hel" + "lo"` | Yes | A constant expression: folded at compile time (checked: `== "hello"` is `true`) |
| `part + "lo"` with `String part = "hel";` | No | Involves a variable, so it's computed at run time (checked: `false`) |
| `part + "lo"` with `final String part = "hel";` | Yes | A `final` variable initialised with a constant is a **constant variable** (JLS §4.12.4) |
| `new String("hello")` | No | Always a new object |
| `s.intern()` | Yes | Returns the pooled instance with the same text (checked: `true`) |
| Strings from input, files, `substring`, `toLowerCase`… | No | Created at run time |

### 3. `==` vs `equals`

| Operation | Compares | Use for |
|---|---|---|
| `a == b` | References: the same object? | Almost never with strings |
| `a.equals(b)` | The characters, exactly | Text equality |
| `a.equalsIgnoreCase(b)` | Characters, ignoring case | User-typed keywords |
| `a.compareTo(b)` | Lexicographic order of UTF-16 units; negative, zero or positive | Sorting |
| `Objects.equals(a, b)` | Like `equals`, but `null`-safe | Values that may be `null` |

```java title="Equality.java"
import java.util.Objects;

public class Equality {
    public static void main(String[] args) {
        String a = "Java";
        String b = "java";
        String c = null;
        System.out.println(a.equals(b) + " " + a.equalsIgnoreCase(b) + " " + a.compareTo(b));
        System.out.println("java".equals(c) + " " + Objects.equals(c, null));
    }
}
```

```text output
false true -32
false true
```

`compareTo` returns the difference of the first differing characters here (`'J'` is 74, `'j'` is 106). Writing the
literal first, `"java".equals(c)`, avoids a `NullPointerException` when `c` is `null`. `==` "works" only when both
sides happen to be the same pooled object, which is exactly what makes it dangerous: see the scenarios.

### 4. `new String("hello")`: how many objects?

The notes say that `new String("hello")` is "stored as a normal object in heap". The classic interview follow-up is
how many objects the line creates:

- The literal `"hello"` refers to a pooled `String`. If no code has used that literal before, it's created when the
  line first runs; if it's already in the pool, nothing new is created for it.
- `new` then **always** creates a second `String` object, outside the pool.

So the answer is **one or two `String` objects**: two the first time the literal is used, one if the literal was
already pooled. (In current JDKs the new String even shares the pooled string's internal byte array, since neither
can change.) The constructor is practically never needed; its own documentation says so, because strings are
immutable.

### 5. Building strings: `+`, `StringBuilder` and friends

A single concatenation expression, `"Hello, " + name + "!"`, is fine: since Java 9 the compiler turns it into one
`invokedynamic` call that sizes and fills the result in one go. The problem is **repeated** concatenation, `s += x` in
a loop, which copies all the text so far on every iteration (the diagram above). Use a `StringBuilder`:

```java title="Building.java"
public class Building {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder();
        for (int i = 1; i <= 5; i++) {
            if (!sb.isEmpty()) {
                sb.append(", ");
            }
            sb.append(i * i);
        }
        System.out.println(sb);
        System.out.println(sb.reverse() + " | " + String.join("-", "a", "b", "c") + " | " + "ab".repeat(3));
    }
}
```

```text output
1, 4, 9, 16, 25
52 ,61 ,9 ,4 ,1 | a-b-c | ababab
```

| Tool | When |
|---|---|
| `a + b + c` | One expression: clear and efficient |
| `StringBuilder` | Building text in loops or across method calls; not thread-safe, and that's fine for locals |
| `StringBuffer` | The old synchronised version (Java 1.0); only for legacy APIs |
| `String.join(sep, parts)` / `Collectors.joining(sep, prefix, suffix)` | Joining collections or streams |
| `"…%s…".formatted(x)` / `String.format` | Templates with formatting (widths, decimals) |

### 6. The everyday API and its traps

| Method | Watch out for |
|---|---|
| `length()`, `charAt(i)` | Count UTF-16 units: `"Hi😀".length()` is 4 (the emoji takes two `char`s); use `codePointCount` or `codePoints()` for characters. `"hello".charAt(5)` throws `StringIndexOutOfBoundsException`: "Index 5 out of bounds for length 5" on JDK 25 |
| `substring(begin, end)` | `end` is exclusive; indexes out of range throw `StringIndexOutOfBoundsException` |
| `indexOf`, `contains`, `startsWith`, `endsWith` | `indexOf` returns `-1` when not found |
| `split(regex)` | A **regular expression**: `split(".")` matches every character; trailing empty strings are dropped unless you pass a negative limit |
| `replace(a, b)` vs `replaceAll(regex, repl)` | `replace` is literal and replaces all occurrences; `replaceAll` is a regex |
| `trim()` vs `strip()` | `trim` removes chars up to U+0020; `strip` (11) removes all Unicode white space |
| `isEmpty()` vs `isBlank()` | `isBlank` (11) is also true for white space only |
| `toUpperCase()`, `toLowerCase()` | Use the default locale: in Turkish, `"title".toUpperCase()` gives `"TİTLE"`. Pass `Locale.ROOT` for identifiers |
| `lines()`, `repeat(n)`, `strip*()` (11), `formatted` (15) | Modern helpers: prefer them to hand-written loops |

### 7. Text blocks

Since Java 15, a **text block** (`"""` followed by a line break) writes multi-line text as it looks (JLS §3.10.6). The
indentation common to all lines, including the line of the closing `"""`, is removed:

```java title="TextBlock.java"
public class TextBlock {
    public static void main(String[] args) {
        String json = """
            {
              "name": "Ada",
              "langs": ["Java", "SQL"]
            }
            """;
        System.out.print(json);
        System.out.println(json.lines().count() + " lines, ends with a newline: " + json.endsWith("\n"));
    }
}
```

```text output
{
  "name": "Ada",
  "langs": ["Java", "SQL"]
}
4 lines, ends with a newline: true
```

Quotes need no escaping inside a text block (only a run of three does). A `\` at the end of a line joins it with the
next, and `\s` keeps a trailing space. A text block is an ordinary `String` constant, pooled like any literal.

<TabItem label="Real world: building a report line">

```java title="Report.java"
import java.util.List;
import java.util.stream.Collectors;

public class Report {
    record Line(String item, int qty) {
    }

    public static void main(String[] args) {
        List<Line> lines = List.of(new Line("pen", 3), new Line("ink", 1), new Line("pad", 2));

        StringBuilder sb = new StringBuilder("Order: ");
        for (Line l : lines) {
            sb.append(l.item()).append(" x").append(l.qty()).append("; ");
        }
        sb.setLength(sb.length() - 2);                  // drop the last "; "
        System.out.println(sb);

        System.out.println(lines.stream()
                .map(l -> l.item() + " x" + l.qty())
                .collect(Collectors.joining("; ", "Order: ", "")));
    }
}
```

```text output
Order: pen x3; ink x1; pad x2
Order: pen x3; ink x1; pad x2
```

Both build the text in one buffer. `Collectors.joining` handles separators, prefix and suffix for you, so there's no
"remove the last separator" step to get wrong.

</TabItem>
<TabItem label="Edge case: == passes the tests">

```java title="Roles.java"
public class Roles {
    static boolean isAdmin(String role) {
        return role == "admin";                                   // compares references
    }

    public static void main(String[] args) {
        System.out.println(isAdmin("admin"));                     // a literal: the pooled object
        System.out.println(isAdmin("ADMIN".toLowerCase()));        // built at run time
        System.out.println(isAdmin(new StringBuilder("admin").toString()));
    }
}
```

```text output
true
false
false
```

A test that passes a literal gets the pooled object and passes; real input is built at run time and fails. Fix:
`return "admin".equals(role);`, which compares the characters and handles `null`. Static analysis tools flag
`==` on strings for exactly this reason.

</TabItem>
<TabItem label="Anti-pattern → fix: += in a loop">

```java title="Anti-pattern"
String csv = "";
for (String line : lines) {           // 100,000 lines
    csv += line + "\n";               // copies everything built so far, every time
}
```

With 100,000 lines of 50 characters, the loop copies about 250 billion characters in total (n²/2 steps of growing
size), and creates 100,000 throw-away strings. The fix is linear:

```java title="Fix"
StringBuilder csv = new StringBuilder(lines.size() * 51);   // optional: size it up front
for (String line : lines) {
    csv.append(line).append('\n');
}
String result = csv.toString();
// or simply: String result = String.join("\n", lines) + "\n";
```

</TabItem>
<TabItem label="Edge case: split surprises">

```java title="Split.java"
import java.util.Arrays;

public class Split {
    public static void main(String[] args) {
        System.out.println(Arrays.toString("1.2.3".split(".")));
        System.out.println(Arrays.toString("1.2.3".split("\\.")));
        System.out.println(Arrays.toString("a,b,,".split(",")));
        System.out.println(Arrays.toString("a,b,,".split(",", -1)));
    }
}
```

```text output
[]
[1, 2, 3]
[a, b]
[a, b, , ]
```

`"."` is a regex that matches every character, so every piece is empty, and trailing empty pieces are removed: nothing
is left. Escape special characters (`"\\."`, or `Pattern.quote(".")`), and pass a negative limit when trailing empty
fields matter, as in CSV. For real CSV (quotes, commas inside fields) use a parser: see the core exercise.

</TabItem>

## Under the hood

<details>
<summary>How HotSpot stores, pools and concatenates strings</summary>

- **Compact strings (Java 9, JEP 254).** A `String` holds a `byte[]` and a `coder` flag: text that fits in Latin-1
  uses one byte per character, anything else two bytes (UTF-16). The API still talks in UTF-16 `char`s; the saving
  is invisible.
- **The pool is a hash table** (HotSpot's StringTable) in native memory that points to `String` objects on the heap.
  Literals are resolved lazily, when the instruction that loads them (`ldc`) first runs. The table holds its strings
  weakly: an interned string that nothing else references can be garbage-collected, while literals stay reachable as
  long as the class using them is loaded. `jcmd <pid> VM.stringtable` prints statistics.
- **Concatenation (Java 9, JEP 280).** `a + b + c` compiles to one `invokedynamic` call bootstrapped by
  `StringConcatFactory`, so the JVM chooses the strategy (sizing the result exactly, then filling it) instead of javac
  emitting a `StringBuilder` chain.
- **`substring` copies.** Since JDK 7u6, substrings get their own array, so a small substring no longer keeps a huge
  original string's array alive.
- **Deduplication.** `-XX:+UseStringDeduplication` lets the garbage collector make equal strings share one internal
  array. That saves memory without changing identity: `==` results stay the same.
- **Reflection can't break immutability any more.** Since JDK 16/17's strong encapsulation, `setAccessible` on
  `String`'s internal field fails with `InaccessibleObjectException` (checked on JDK 25).

</details>

## Myths vs facts

<MythVsFact myth="== compares the text of two strings.">
`==` compares references. It returns `true` for equal text only when both sides are the same object, typically two
literals. Strings built at run time (input, concatenation with variables, `substring`, `toLowerCase`) are different
objects, so use `equals`.
</MythVsFact>

<MythVsFact myth="The String Constant Pool lives in PermGen or Metaspace, outside the heap." audit="6.5">
The notes have it right: it's part of the heap, and has been since Java 7. PermGen was removed in Java 8; Metaspace
holds class metadata, not string objects.
</MythVsFact>

<MythVsFact myth={'new String("hello") always creates exactly two objects.'} audit="6.6">
It creates **one or two** `String` objects: the `new` one always, and the pooled literal only if no code has used
`"hello"` before. The rest of the answer interviewers look for: the new object is outside the pool, and
`intern()` gets you back to the pooled one.
</MythVsFact>

<MythVsFact myth="Using + for strings is always slow: always use StringBuilder.">
A single `+` expression is compiled into one efficient concatenation (Java 9+). `StringBuilder` matters when you build
a string step by step, especially in loops, where `+=` copies everything on every iteration.
</MythVsFact>

<MythVsFact myth="Pooled strings are never garbage-collected.">
Interned strings that nothing references can be collected. Literals stay alive only because their class refers to
them, for as long as that class is loaded.
</MythVsFact>

## Doubts cleared

<FaqItem q="Why did the Java designers make strings immutable?">
For safe sharing (pooling, use as map keys, use from many threads without locks), security (checked names and paths
can't change afterwards) and performance (the hash code is cached). The cost, a new object per change, is solved by
`StringBuilder`.
</FaqItem>

<FaqItem q="Should I call intern() to save memory?">
Rarely. It trades CPU (a table lookup) for memory, and only pays off for huge numbers of duplicate strings that live
long. Measure first; deduplicating in your own map or using the GC's string deduplication are alternatives. Never
intern so that you can use `==`.
</FaqItem>

<FaqItem q="What's the difference between StringBuilder and StringBuffer?">
Same API; `StringBuffer`'s methods are synchronised. A builder is almost always local to one method, so
`StringBuilder` is the right choice; `StringBuffer` remains for old APIs.
</FaqItem>

<FaqItem q={'Why does "Hi😀".length() return 4?'}>
`length()` counts UTF-16 code units, and characters outside the Basic Multilingual Plane, like most emoji, take two
(a surrogate pair). `codePointCount(0, s.length())` returns 3. See [char & boolean](/lessons/char-and-boolean/).
</FaqItem>

<FaqItem q="How does switch on a String work?">
The compiler switches on `hashCode()` and then confirms with `equals`. A `null` selector throws
`NullPointerException` unless there's a `case null` (Java 21) ([switch Statements & Expressions](/lessons/switch-statements-and-expressions/)).
</FaqItem>

<FaqItem q="Can I change a String through reflection?">
Not in modern Java: `String`'s internal field is in `java.base`, which is strongly encapsulated, so making it
accessible fails with `InaccessibleObjectException`. That keeps immutability a guarantee, not a convention.
</FaqItem>

<FaqItem q="Why pass a Locale to toUpperCase?">
Case rules depend on the language: Turkish has a dotted and a dotless i, so `"title".toUpperCase()` with a Turkish
default locale gives `"TİTLE"`. For identifiers, protocol keywords and keys, use `Locale.ROOT`.
</FaqItem>

<FaqItem q="Does substring share memory with the original string?">
Not since JDK 7u6: it copies the characters it needs. That costs a copy but prevents a small substring from keeping a
large text alive.
</FaqItem>

<FaqItem q="Does Java have string interpolation?">
Not in Java 25. String templates were previewed in Java 21 and 22 and then withdrawn. Use `+`, `formatted`, or
`MessageFormat`.
</FaqItem>

## Pitfalls and best practices

| ✅ Do | ❌ Don't |
|---|---|
| Compare text with `equals`, `"literal".equals(x)` or `Objects.equals` | Compare strings with `==` |
| Keep the result of `toUpperCase`, `trim`, `replace`… | Call them and ignore the returned string |
| Use `StringBuilder`, `String.join` or `Collectors.joining` in loops | Build strings with `+=` inside loops |
| Escape regex characters in `split`, pass `-1` to keep empty fields | Assume `split` takes plain text |
| Use `Locale.ROOT` for case conversion of identifiers | Rely on the default locale for keys and protocols |
| Count characters with `codePointCount` when emoji or rare scripts matter | Use `length()` as "number of characters" for user text |

## Senior lens

<Callout type="senior" title="Explain it to your team in 60 seconds">
"Strings are immutable, so they're safe to share, pool and use as keys, and every 'change' creates a new one. Literals
and constant expressions are pooled in the heap, so `==` sometimes looks like it works: never rely on it, use
`equals`. One `+` expression is efficient; building in a loop needs a `StringBuilder` or `joining`. Watch the API
traps: `split` is a regex, `length()` counts UTF-16 units, case conversion needs a locale."
</Callout>

**Where strings hurt in production**

| Symptom | Cause | Fix |
|---|---|---|
| A check that works in tests fails with real input | `==` on strings | `equals`; a static-analysis rule |
| CPU and GC churn while building large text | `+=` in loops | `StringBuilder` or `joining`, sized up front |
| Many duplicate strings in a heap dump | Repeated values from parsing (country codes, statuses) | Enums, a small dedup map, or GC string deduplication |
| Wrong results for Turkish or other users | Default-locale `toUpperCase`/`toLowerCase` | `Locale.ROOT` for machine text |
| Truncated or garbled emoji | Cutting at `char` positions | Work with code points or `BreakIterator` |

**Code-review checklist**
- [ ] No `==` or `!=` between strings.
- [ ] No ignored return values of `String` methods.
- [ ] No `+=` on strings inside loops.
- [ ] `split` arguments are valid, escaped regexes; limits chosen deliberately.
- [ ] Case conversions of identifiers use `Locale.ROOT`.

```java title="Texts.java (solution)"
package track.strings;

/** Reference solution for the Texts exercise. */
public final class Texts {

    private Texts() {
    }

    public static String reverse(String s) {
        return new StringBuilder(s).reverse().toString();     // keeps surrogate pairs in order
    }

    public static boolean isPalindrome(String s) {
        int[] kept = s.codePoints().filter(Character::isLetterOrDigit).map(Character::toLowerCase).toArray();
        for (int i = 0, j = kept.length - 1; i < j; i++, j--) {
            if (kept[i] != kept[j]) {
                return false;
            }
        }
        return true;
    }

    public static int countOccurrences(String text, String word) {
        if (word.isEmpty()) {
            throw new IllegalArgumentException("empty word");
        }
        int count = 0;
        for (int i = text.indexOf(word); i >= 0; i = text.indexOf(word, i + word.length())) {
            count++;
        }
        return count;
    }

    public static String compress(String s) {
        StringBuilder out = new StringBuilder();
        int i = 0;
        while (i < s.length()) {
            char c = s.charAt(i);
            int j = i;
            while (j < s.length() && s.charAt(j) == c) {
                j++;
            }
            out.append(c).append(j - i);
            i = j;
        }
        return out.toString();
    }
}
```

```java title="Csv.java (solution)"
package track.strings;

import java.util.ArrayList;
import java.util.List;
import java.util.Objects;

/** Reference solution for the Csv exercise. */
public final class Csv {

    private Csv() {
    }

    public static String format(List<List<String>> rows) {
        StringBuilder out = new StringBuilder();
        for (List<String> row : rows) {
            if (row.isEmpty()) {
                throw new IllegalArgumentException("a row needs at least one field");
            }
            for (int i = 0; i < row.size(); i++) {
                if (i > 0) {
                    out.append(',');
                }
                appendField(out, Objects.requireNonNull(row.get(i), "field"));
            }
            out.append('\n');
        }
        return out.toString();
    }

    private static void appendField(StringBuilder out, String field) {
        boolean quote = field.isEmpty() || field.chars().anyMatch(c -> c == ',' || c == '"' || c == '\n' || c == '\r');
        if (!quote) {
            out.append(field);
            return;
        }
        out.append('"');
        for (int i = 0; i < field.length(); i++) {
            char c = field.charAt(i);
            if (c == '"') {
                out.append('"');                        // a quote inside quotes is written twice
            }
            out.append(c);
        }
        out.append('"');
    }

    public static List<List<String>> parse(String text) {
        List<List<String>> rows = new ArrayList<>();
        if (text.isEmpty()) {
            return rows;
        }
        List<String> row = new ArrayList<>();
        StringBuilder field = new StringBuilder();    // reused for every field
        int n = text.length();
        int i = 0;
        while (true) {
            if (i < n && text.charAt(i) == '"') {       // a quoted field
                i++;
                while (true) {
                    if (i >= n) {
                        throw new IllegalArgumentException("unterminated quoted field");
                    }
                    char c = text.charAt(i);
                    if (c != '"') {
                        field.append(c);
                        i++;
                    } else if (i + 1 < n && text.charAt(i + 1) == '"') {
                        field.append('"');              // a doubled quote
                        i += 2;
                    } else {
                        i++;                            // the closing quote
                        break;
                    }
                }
                if (i < n && !isSeparator(text.charAt(i))) {
                    throw new IllegalArgumentException("unexpected character after a closing quote at " + i);
                }
            } else {                                    // an unquoted field
                while (i < n && !isSeparator(text.charAt(i))) {
                    if (text.charAt(i) == '"') {
                        throw new IllegalArgumentException("quote inside an unquoted field at " + i);
                    }
                    field.append(text.charAt(i++));
                }
            }
            row.add(field.toString());
            field.setLength(0);
            if (i >= n) {
                rows.add(row);
                return rows;
            }
            char c = text.charAt(i);
            if (c == ',') {
                i++;
                continue;
            }
            if (c == '\r') {
                if (i + 1 >= n || text.charAt(i + 1) != '\n') {
                    throw new IllegalArgumentException("carriage return without a line feed at " + i);
                }
                i++;
            }
            i++;                                        // past the '\n'
            rows.add(row);
            row = new ArrayList<>();
            if (i >= n) {
                return rows;                            // a final line break ends the input
            }
        }
    }

    private static boolean isSeparator(char c) {
        return c == ',' || c == '\n' || c == '\r';
    }
}
```

```java title="MiniBuilderTest.java"
                if (sb.length() > capacity[0]) {                    // the growth rule, as a model
                    copied[0] += len;
                    capacity[0] = Math.max(sb.length(), 2 * capacity[0] + 2);
                }
                assertThat(mb.toString()).isEqualTo(sb.toString());
                assertThat(mb.length()).isEqualTo(sb.length());
                assertThat(mb.capacity()).isEqualTo(capacity[0]);
                assertThat(mb.charsCopied()).isEqualTo(copied[0]);
                if (sb.length() > 0) {
                    int k = random.nextInt(sb.length());
                    assertThat(mb.charAt(k)).isEqualTo(sb.charAt(k));
                }
            }
        }
    }

    /** Runs an operation on both; if StringBuilder rejects it, MiniBuilder must reject it too. */
    private static void run(StringBuilder sb, MiniBuilder mb, Consumer<StringBuilder> onSb, Consumer<MiniBuilder> onMb) {
        RuntimeException failure = null;
        try {
            onSb.accept(sb);
        } catch (RuntimeException e) {
            failure = e;
        }
        if (failure == null) {
            onMb.accept(mb);
        } else {
            assertThat(failure).isInstanceOf(IndexOutOfBoundsException.class);
            assertThatThrownBy(() -> onMb.accept(mb)).isInstanceOf(IndexOutOfBoundsException.class);
        }
    }
}
```

```java title="MiniBuilder.java (solution)"
package track.strings;

/** Reference solution for the MiniBuilder exercise. */
public final class MiniBuilder {
    private char[] value;
    private int count;
    private long charsCopied;

    public MiniBuilder() {
        value = new char[16];
    }

    public MiniBuilder(String s) {
        value = new char[s.length() + 16];
        s.getChars(0, s.length(), value, 0);
        count = s.length();
    }

    public MiniBuilder append(String s) {
        String text = String.valueOf(s);                // null → "null"
        ensureCapacity(count + text.length());
        text.getChars(0, text.length(), value, count);
        count += text.length();
        return this;
    }

    public MiniBuilder append(char c) {
        ensureCapacity(count + 1);
        value[count++] = c;
        return this;
    }

    public MiniBuilder append(int i) {
        return append(Integer.toString(i));
    }

    public MiniBuilder insert(int index, String s) {
        if (index < 0 || index > count) {
            throw new StringIndexOutOfBoundsException("offset " + index + ", length " + count);
        }
        String text = String.valueOf(s);
        ensureCapacity(count + text.length());
        System.arraycopy(value, index, value, index + text.length(), count - index);   // open a gap
        text.getChars(0, text.length(), value, index);
        count += text.length();
        return this;
    }

    public MiniBuilder delete(int start, int end) {
        int stop = Math.min(end, count);
        if (start < 0 || start > stop) {
            throw new StringIndexOutOfBoundsException("start " + start + ", end " + end + ", length " + count);
        }
        System.arraycopy(value, stop, value, start, count - stop);                    // close the gap
        count -= stop - start;
        return this;
    }

    public MiniBuilder deleteCharAt(int index) {
        checkIndex(index);
        return delete(index, index + 1);
    }

    public MiniBuilder reverse() {
        for (int i = 0, j = count - 1; i < j; i++, j--) {
            char t = value[i];
            value[i] = value[j];
            value[j] = t;
        }
        for (int i = 0; i < count - 1; i++) {         // a reversed pair reads low, high: swap it back
            if (Character.isLowSurrogate(value[i]) && Character.isHighSurrogate(value[i + 1])) {
                char t = value[i];
                value[i] = value[i + 1];
                value[i + 1] = t;
                i++;
            }
        }
        return this;
    }

    public void setCharAt(int index, char c) {
        checkIndex(index);
        value[index] = c;
    }

    public char charAt(int index) {
        checkIndex(index);
        return value[index];
    }

    public int length() {
        return count;
    }

    public int indexOf(String s) {
        outer:
        for (int i = 0; i + s.length() <= count; i++) {
            for (int k = 0; k < s.length(); k++) {
                if (value[i + k] != s.charAt(k)) {
                    continue outer;
                }
            }
            return i;
        }
        return -1;
    }

    public int capacity() {
        return value.length;
    }

    public long charsCopied() {
        return charsCopied;
    }

    @Override
    public String toString() {
        return new String(value, 0, count);
    }

    private void ensureCapacity(int needed) {
        if (needed > value.length) {
            char[] bigger = new char[Math.max(needed, 2 * value.length + 2)];
            System.arraycopy(value, 0, bigger, 0, count);
            charsCopied += count;
            value = bigger;
        }
    }

    private void checkIndex(int index) {
        if (index < 0 || index >= count) {
            throw new StringIndexOutOfBoundsException("index " + index + ", length " + count);
        }
    }
}
```

## Cheat sheet

<CheatSheet>

| Topic | Remember |
|---|---|
| **String** | Final class, immutable UTF-16 text; methods return new strings |
| **Pool** | In the heap (Java 7+); literals and constant expressions share one object |
| **new String("x")** | Always a new object outside the pool: one or two String objects created |
| **intern()** | Returns the pooled instance with the same text |
| **Equality** | `equals` for text, `==` for identity; `"lit".equals(x)` or `Objects.equals` for null safety |
| **Building** | One `+` expression is fine; loops need `StringBuilder` / `join` / `joining` |
| **StringBuffer** | Synchronised legacy twin of StringBuilder |
| **Traps** | `split` is a regex and drops trailing empties; `length()` counts UTF-16 units; `toUpperCase` needs `Locale.ROOT` for identifiers |
| **Text blocks** | `"""` (15): incidental indentation removed, pooled like literals |
| **Modern API** | `strip`, `isBlank`, `lines`, `repeat` (11); `formatted` (15) |

</CheatSheet>
