## Why this matters

A library ships a class with a `public` field `timeoutMillis` "for convenience". Two years later the maintainers want
to validate it, compute it lazily, or rename it, and they can't: hundreds of applications read and write that field
directly, and every change would break them. Access modifiers decide **what other code is allowed to depend on**. The
narrower the access, the freer you are to change your code later; the wider, the more of it becomes a promise. Packages
decide the neighbourhoods those rules apply to.

## TL;DR

<Callout type="tldr">
- A **package** is a namespace and a folder: `package com.shop.billing;` puts a class in `com/shop/billing/`, and its
  full name becomes `com.shop.billing.Invoice`.
- **Imports** only save typing: `import java.util.List;`, `import java.util.*;` (not subpackages),
  `import static java.lang.Math.max;`, and since Java 25 `import module java.base;`. `java.lang` is always imported.
- Four access levels: **`public`** (everywhere), **`protected`** (package + subclasses), **no modifier** =
  package-private (same package), **`private`** (the class and its nested classes).
- `protected` from a subclass in another package works only **through the subclass's own type**, not through a
  reference to the parent.
- `private` is per **class**, not per object: an object can read another instance's private fields.
- Top-level classes are only `public` or package-private. Start with the narrowest access and widen on purpose.
</Callout>

## Mental model

Think of an **office building**. Your desk drawer is `private`: only you (and the notes pinned inside it, the nested
classes) can open it. Your team's room is the **package**: anyone in the room can use what's on the shared shelf
(package-private). `protected` is the room plus your apprentices working in other rooms, who can use what they
inherited from you. The lobby is `public`: anyone from any building can walk in.

Where it breaks: packages aren't nested rooms. `com.shop` and `com.shop.billing` are two **unrelated** rooms that
happen to have similar names.

## Concept, step by step

### 1. Packages

A package groups related types under one name. The `package` declaration is the first statement of the file, and the
file lives in the matching folder:

<FileTree>
- src/
  - com/
    - shop/
      - billing/
        - Invoice.java `package com.shop.billing;`
        - TaxRules.java `package com.shop.billing;`
      - catalog/
        - Product.java `package com.shop.catalog;`
</FileTree>

- The **fully qualified name** of a class is its package plus its name: `com.shop.billing.Invoice`. Two classes can
  share a simple name if their packages differ (`java.util.Date` and `java.sql.Date`).
- By convention, package names are lower case and start with a reversed domain you control (`com.example.app`,
  `org.acme.billing`), so they don't clash with other people's code (JLS §6.1).
- A file without a `package` line belongs to the **unnamed package**. That's fine for one-file experiments, but classes
  in named packages can't import from it, so real code always declares a package.
- Packages are **not hierarchical** for the language: `com.shop.billing` has no special access to `com.shop`. The dots
  only mirror the folders.

### 2. Imports

Imports let you write `List` instead of `java.util.List`. They are a compile-time convenience only: nothing is copied
into your class, and they have no run-time cost.

```java title="Imports.java"
import java.util.ArrayList;          // single-type import
import java.util.List;
import java.util.concurrent.*;       // on-demand: every type of that one package
import static java.lang.Math.max;    // static import: a static member

public class Imports {
    public static void main(String[] args) {
        List<Integer> list = new ArrayList<>(List.of(3, 9, 4));
        ConcurrentMap<String, Integer> totals = new ConcurrentHashMap<>();
        totals.put("max", max(list.get(0), list.get(1)));
        System.out.println(totals);                  // String, System: java.lang, always imported
    }
}
```

```text output
{max=9}
```

Rules worth knowing:

| Situation | Result |
|---|---|
| `import java.util.*;` | Imports `java.util.List`, not `java.util.function.Function`: subpackages are separate packages |
| A single-type import and an on-demand import both offer `List` | The single-type import wins |
| Two on-demand imports both offer `Date` (`java.util.*`, `java.sql.*`) | Compiles until you use `Date`, then "reference to Date is ambiguous"; use a single-type import or the full name |
| Same simple name needed twice in one file | Import one, write the other in full: `java.sql.Date` |

Since Java 25, `import module java.base;` imports every public type of the packages a module exports (JEP 511), and a
compact source file imports `java.base` automatically ([Your First Program](/lessons/first-program/)).

### 3. The four access levels

The notes list four "access specifiers"; the language calls them **access modifiers**, and they apply to fields,
methods, constructors and nested types, not only to methods:

| Modifier | Same class (+ nested) | Same package | Subclass in another package | Any other code |
|---|:---:|:---:|:---:|:---:|
| `public` | ✅ | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ✅ through its own type | ❌ |
| none (package-private) | ✅ | ✅ | ❌ | ❌ |
| `private` | ✅ | ❌ | ❌ | ❌ |

- **No keyword** gives package-private access. The notes call it "default"; `default` is a different keyword (in
  `switch` and interface methods), so "package-private" avoids confusion.
- `protected` **includes** package access: every class in the same package can use a protected member.
- **Top-level classes** can only be `public` or package-private (a `private` top-level class could be used by nobody).
  A file may contain several top-level classes, but at most one `public` one, and it must be named like the file.
- Access applies to **code**, not to objects: the rules ask "where is the code that uses this member?", never "which
  object is it?".

### 4. `private` is per class, not per object

Because access is about where the code is, a method of `Money` can read the private fields of **another** `Money`:

```java title="Money.java"
public final class Money {
    private final long cents;

    public Money(long cents) {
        this.cents = cents;
    }

    public boolean isMoreThan(Money other) {
        return this.cents > other.cents;     // other's private field: allowed
    }

    public static void main(String[] args) {
        System.out.println(new Money(500).isMoreThan(new Money(250)));
    }
}
```

```text output
true
```

That's what makes `equals`, `compareTo` and copy constructors possible without getters. Private members are also
shared with **nested classes**: the top-level class and everything nested in it form a **nest** (Java 11, JEP 181),
and they can use each other's private members.

### 5. The `protected` subtlety

`protected` does **not** mean "any subclass can access it through any reference". In a subclass in **another**
package, a protected instance member can be used only through references whose type is that subclass (or its own
subclasses), including `this` (JLS §6.6.2.1):

```java title="bank/core/Account.java"
package bank.core;

public class Account {
    protected long balance;                  // package + subclasses
}
```

```java title="bank/products/Savings.java"
package bank.products;

import bank.core.Account;

public class Savings extends Account {
    void addInterest(Savings other, Account any) {
        balance += 10;                       // OK: this object's inherited field
        other.balance += 10;                 // OK: through a Savings reference
        any.balance += 10;                   // compile error: balance has protected access in Account
    }
}
```

The reason: `any` might be a completely different kind of `Account` (a `Checking`, written by someone else), and
`Savings` has no business changing its internals. Static protected members don't have this restriction:
`Account.someStaticField` is fine anywhere in the subclass. The notes' description ("other subclasses in different
package") misses this rule, and it's a classic interview question.

### 6. Access and overriding

When a subclass overrides a method, it may keep or **widen** the access, never narrow it: a `public` method can't be
overridden by a `protected` one, because code holding a parent reference must still be able to call it ("attempting to
assign weaker access privileges"). [Polymorphism](/lessons/polymorphism/) covers the other overriding rules. Private
methods aren't inherited, so a subclass method with the same name is a new method, not an override.

### 7. Modules add one more layer

Since Java 9, packages can be grouped into **modules**. A module's `module-info.java` lists the packages it
**exports**; a `public` class in a package that isn't exported is not accessible from other modules. That's how the
JDK hides its internals (`sun.misc`, `jdk.internal`), strongly enforced since Java 17 (JEP 403). For application code
on the class path nothing changes; libraries can use modules to keep "public but internal" packages private.

### 8. Choosing access

1. Fields: **`private`** (almost always), exposed through methods if needed ([Encapsulation](/lessons/encapsulation/)).
2. Helpers: **`private`**, or package-private when other classes of the package need them (and tests).
3. Classes that are implementation details: **package-private**, behind a public interface or factory.
4. **`public`** only for what other packages are meant to use, and **`protected`** only for what subclasses in other
   packages are meant to override or use: both are promises you'll have to keep.

<TabItem label="Anti-pattern → fix: public fields">

```java title="Anti-pattern"
public class Connection {
    public int timeoutMillis = 5000;       // anyone can set -1
}
```

```java title="Fix"
public class Connection {
    private int timeoutMillis = 5000;

    public int timeoutMillis() {
        return timeoutMillis;
    }

    public void setTimeoutMillis(int millis) {
        if (millis <= 0) {
            throw new IllegalArgumentException("timeout must be positive: " + millis);
        }
        this.timeoutMillis = millis;
    }
}
```

The field can now be validated, logged, renamed or computed differently without breaking callers. Records do this
automatically for immutable data: their fields are `private final` and their accessors `public`.

</TabItem>

## Under the hood

<details>
<summary>How access is stored and checked</summary>

- **Class-file flags.** `public`, `protected` and `private` are flags on each class, field and method (`ACC_PUBLIC`,
  `ACC_PROTECTED`, `ACC_PRIVATE`); package-private is simply the absence of all three (JVMS §4.1, §4.5, §4.6).
- **Two checks.** `javac` checks access at compile time. The JVM checks it again when it links a reference at run time
  (JVMS §5.4.4): if a class was recompiled with narrower access and its callers weren't, the call fails with
  `IllegalAccessError` rather than silently working.
- **Run-time packages.** At run time a package is identified by its name **and** its class loader (JVMS §5.3):
  classes with the same package name loaded by different loaders don't get package-private access to each other.
- **Nest-mates.** Before Java 11, a nested class reading its outer class's private field went through generated
  `access$000` methods. Since JEP 181, the class file records the nest (`NestHost`, `NestMembers`) and the JVM allows
  private access within it directly.
- **Reflection.** `setAccessible(true)` can bypass `private`, unless the module system forbids it: deep reflection
  into a package that isn't opened throws `InaccessibleObjectException` (Java 9+).

</details>

## Myths vs facts

<MythVsFact myth="Java has four access specifiers, and they are about methods." audit="7.3">
The JLS calls them **access modifiers**: three keywords (`public`, `protected`, `private`) plus no modifier
(package-private). They apply to fields, constructors and nested types as well as methods, and top-level classes can
only be `public` or package-private.
</MythVsFact>

<MythVsFact myth="protected members can be used by any subclass, through any reference." audit="7.3">
In a subclass in **another** package, a protected instance member is accessible only through references of that
subclass's type (or its subclasses), including `this`. Through a reference of the parent type it's a compile error
(JLS §6.6.2.1). Within the same package, protected behaves like package-private (and more).
</MythVsFact>

<MythVsFact myth="private means only the same object can see it.">
`private` is per **class** (and its nest), not per object: any code in the class can use the private members of any
instance of it, which is exactly what `equals` and `compareTo` do.
</MythVsFact>

<MythVsFact myth="import java.util.* makes the program slower or bigger, and includes java.util.function too.">
Imports are resolved by the compiler and leave no trace at run time, whichever form you use. An on-demand import
covers one package only; subpackages are separate packages and need their own imports.
</MythVsFact>

<MythVsFact myth="com.shop.billing is inside com.shop, so it can see com.shop's package-private classes.">
Packages aren't nested for access. Each package is its own unit; the dotted names only mirror the folder structure.
</MythVsFact>

## Doubts cleared

<FaqItem q="Why can't a top-level class be private or protected?">
There's nothing around a top-level class to be private *to*, and `protected` is about subclasses of an enclosing
class. Nested classes can use all four modifiers.
</FaqItem>

<FaqItem q="Can one file hold two public classes?">
No. A file can contain several top-level classes, but at most one `public` one, named like the file (`Invoice.java`
for `public class Invoice`). Nested classes don't count.
</FaqItem>

<FaqItem q="What access do interface members have?">
Interface methods are implicitly `public` (since Java 9 they can also be `private` helpers), and interface fields are
implicitly `public static final`. Writing `public` on them is allowed but redundant.
</FaqItem>

<FaqItem q="What access do enum constructors and record fields have?">
Enum constructors are implicitly `private` (nobody else may create constants). A record's fields are
`private final`, its generated accessor methods are `public`, and its generated canonical constructor has the same
access as the record itself.
</FaqItem>

<FaqItem q="How do I test package-private code?">
Put the test class in the **same package** (usually a parallel folder, `src/test/java/com/shop/billing/`). Same
package name means package access, even though the files live in different folders.
</FaqItem>

<FaqItem q="Is it OK to use the unnamed (default) package?">
For single-file experiments and scripts, yes. For anything that grows, no: other packages can't import its classes,
and name clashes become likely.
</FaqItem>

<FaqItem q="What does import static add?">
It lets you use a class's **static** members without the class name: `max(a, b)` instead of `Math.max(a, b)`. Use it
sparingly (test assertions, constants) so readers can still tell where a name comes from.
</FaqItem>

<FaqItem q="Can reflection break private?">
Within the class path, `setAccessible(true)` can read private members (frameworks rely on it). Modules restrict it:
code can't reflect deeply into packages a module doesn't open. Access modifiers are a design tool, not a security
boundary against code running in the same JVM.
</FaqItem>

<FaqItem q="protected or package-private for a method subclasses need?">
If the subclasses live in the same package, package-private is enough and keeps the method out of the API. Use
`protected` only when subclasses in other packages must override or call it, and document it: it's part of your
class's contract.
</FaqItem>

## Pitfalls and best practices

| ✅ Do | ❌ Don't |
|---|---|
| Make fields `private` and expose behaviour through methods | Make fields `public` "for convenience" |
| Default to the narrowest access that works | Start `public` and hope to narrow later |
| Package by feature so most classes can be package-private | Make every class `public` because layers call each other |
| Use `protected` only for designed extension points | Use `protected` as "a bit more private than public" |
| Put tests in the same package to test package-private code | Widen access just for tests |
| Import what you use; write clashing names in full | Rely on on-demand imports that become ambiguous |

## Senior lens

<Callout type="senior" title="Explain it to your team in 60 seconds">
"Every `public` and `protected` member is an API promise; everything else we can change freely. So fields are private,
helpers are private or package-private, implementation classes are package-private behind a public interface or
factory, and we package by feature so that's possible. `protected` is for designed extension points only, and from
another package it works only through the subclass's own type. Libraries can go one step further with modules and
export only their API packages."
</Callout>

**Access decisions and their cost**

| Choice | You gain | You give up |
|---|---|---|
| `public` class or member | Anyone can use it | Freedom to change it (semantic versioning, deprecation cycles) |
| `protected` member | Subclasses elsewhere can extend behaviour | Freedom to change it, plus the fragile base class problem |
| Package-private | Free collaboration inside the package, testability | Nothing outside the package can use it |
| `private` | Complete freedom to change | Nothing, until another class really needs it |
| Module exports | Strong encapsulation of internal packages | Some build complexity |

**Code-review checklist**
- [ ] No `public` or `protected` fields (constants excepted).
- [ ] New `public` types and members are really meant for other packages.
- [ ] Implementation classes are package-private; the package exposes interfaces or factories.
- [ ] `protected` members are documented as extension points.
- [ ] Tests don't force wider access than production needs.

## Modern Java

- <VersionBadge since={5} /> Static imports.
- <VersionBadge since={9} /> Modules (`module-info.java`, `exports`, `opens`) and `private` interface methods.
- <VersionBadge since={11} jep={181} /> Nest-based access control: nested classes share private access without
  synthetic accessor methods.
- <VersionBadge since={16} jep={396} /> JDK internals strongly encapsulated by default; <VersionBadge since={17} jep={403} />
  no way to switch that off with `--illegal-access`.
- <VersionBadge since={17} jep={409} /> Sealed classes: `permits` lists which classes may extend a type, a new tool
  next to access modifiers for controlling extension ([Sealed Classes](/lessons/sealed-classes/)).
- <VersionBadge since={25} jep={511} /> Module import declarations: `import module java.base;`.

<Tests>

```java title="AccountTest.java"
package track.packages_access_modifiers;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatIllegalArgumentException;
import static org.assertj.core.api.Assertions.assertThatIllegalStateException;
import static org.assertj.core.api.Assertions.assertThatNullPointerException;

import java.lang.reflect.Modifier;
import org.junit.jupiter.api.Test;

class AccountTest {

    private static boolean packagePrivate(int m) {
        return !Modifier.isPublic(m) && !Modifier.isProtected(m) && !Modifier.isPrivate(m);
    }

    @Test
    void membersHaveTheNarrowestAccess() throws Exception {
        int owner = Account.class.getDeclaredField("owner").getModifiers();
        int balance = Account.class.getDeclaredField("balance").getModifiers();
        assertThat(Modifier.isPrivate(owner) && Modifier.isFinal(owner)).as("owner is private final").isTrue();
        assertThat(Modifier.isPrivate(balance)).as("balance is private").isTrue();
```

```java title="Account.java (solution)"
package track.packages_access_modifiers;

import java.util.Objects;

/** Reference solution for the Account exercise. */
public class Account {
    private final String owner;                  // never changes: private final
    private long balance;                        // changes, but only through deposit/withdraw

    public Account(String owner) {
        this.owner = Objects.requireNonNull(owner, "owner");
    }

    public void deposit(long cents) {
        requirePositive(cents);
        balance += cents;
    }

    public void withdraw(long cents) {
        requirePositive(cents);
        if (cents > balance) {
            throw new IllegalStateException("insufficient funds: " + balance + " < " + cents);
        }
        balance -= cents;
    }

    public long balanceCents() {
        return balance;
    }

    public String owner() {
        return owner;
    }

    /** Package-private: for the bank's own reports in this package, not for customers. */
    String auditLine() {
        return owner + ": " + balance;
    }

    private static void requirePositive(long cents) {
        if (cents <= 0) {
            throw new IllegalArgumentException("amount must be positive: " + cents);
        }
    }
}
```

```java title="Sensors.java (solution)"
package track.packages_access_modifiers.sensors;

/** Reference solution: the only public entry point of the package. */
public final class Sensors {

    private Sensors() {                              // a utility class: no instances
    }

    public static Sensor simulated(String id, double start, double step) {
        return new SimulatedSensor(requireId(id), start, step);
    }

    public static Sensor fixed(String id, double value) {
        return new FixedSensor(requireId(id), value);
    }

    static String requireId(String id) {             // package-private: SimulatedSensor could reuse it
        if (id == null || id.isBlank()) {
            throw new IllegalArgumentException("a sensor needs an id");
        }
        return id;
    }

    /** Visible only inside Sensors (and its nest). */
    private static final class FixedSensor implements Sensor {
        private final String id;
        private final double value;

        private FixedSensor(String id, double value) {
            this.id = id;
            this.value = value;
        }

        @Override
        public String id() {
            return id;
        }

        @Override
        public double read() {
            return value;
        }
    }
}
```

```java title="AccessRules.java (solution)"
package track.packages_access_modifiers;

/** Reference solution for the AccessRules exercise. */
public final class AccessRules {

    public enum Access { PUBLIC, PROTECTED, PACKAGE_PRIVATE, PRIVATE }

    public enum Place { SAME_CLASS, NESTED_CLASS, SAME_PACKAGE, SUBCLASS_VIA_SUBCLASS, SUBCLASS_VIA_PARENT, OTHER_PACKAGE }

    private AccessRules() {
    }

    public static boolean canAccess(Access access, Place place, boolean isStatic) {
        return switch (access) {
            case PUBLIC -> true;
            case PRIVATE -> place == Place.SAME_CLASS || place == Place.NESTED_CLASS;      // the whole nest
            case PACKAGE_PRIVATE -> switch (place) {
                case SAME_CLASS, NESTED_CLASS, SAME_PACKAGE -> true;
                case SUBCLASS_VIA_SUBCLASS, SUBCLASS_VIA_PARENT, OTHER_PACKAGE -> false;   // not inherited across packages
            };
            case PROTECTED -> switch (place) {
                case SAME_CLASS, NESTED_CLASS, SAME_PACKAGE, SUBCLASS_VIA_SUBCLASS -> true;
                case SUBCLASS_VIA_PARENT -> isStatic;     // JLS §6.6.2.1: instance members only via the subclass type
                case OTHER_PACKAGE -> false;
            };
        };
    }
}
```

## Cheat sheet

<CheatSheet>

| Topic | Remember |
|---|---|
| **Package** | `package a.b;` first line; folder `a/b/`; full name `a.b.Type`; reverse-domain names; not hierarchical for access |
| **Imports** | single-type > on-demand; `*` = one package, no subpackages; `import static`; `java.lang` automatic; Java 25 `import module` |
| **public** | everywhere |
| **protected** | package + subclasses; from another package only through the subclass's type (statics: any qualifier) |
| **no modifier** | package-private: the same package only |
| **private** | the class and its nested classes; per class, not per object |
| **Top-level classes** | `public` or package-private; one public class per file, named like the file |
| **Overriding** | may widen access, never narrow it |
| **Design** | private fields, package-private implementation, small public API; `protected` = extension point |

</CheatSheet>
